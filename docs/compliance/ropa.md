# Record of Processing Activities (GDPR Art. 30)
Updated by the reviewer whenever a spec adds or changes a data flow. Source of truth for the privacy policy's tables. See `plan/07-compliance.md` §1.2 for the initial flows.

**Cookies and client storage:** `cookie-register.md` in this directory is the register of every
cookie and storage key the application sets, with its classification, lifetime and the user action
that creates it — and since spec 004 its table is generated from `src/config/cookies.ts`
(`pnpm cookies:check`). It is the source of truth for the cookie policy page, as this file is for
the privacy policy's processing tables.

**One env variable is a RoPA-affecting act.** Setting `NEXT_PUBLIC_GA4_MEASUREMENT_ID` activates
row 4 below: Google becomes an active processor, the privacy policy must already name it, and the
data-processing terms must already be accepted and filed. The procedure, the order of the steps and
what must be true before the variable is set are in `docs/runbooks/analytics-consent.md`. No code
change is involved, which is exactly why it needs a runbook — a value pasted into an env store is
the easiest way to acquire an undeclared processor.
