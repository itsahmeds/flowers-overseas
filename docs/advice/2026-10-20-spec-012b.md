# Spec 012b: catalogue CMS

## 1. In one sentence
Slice A moves bouquets, prices, photos and countries into the database and adds a Publish button that rebuilds the live version, which is the right design and answers every point the 2026-10-04 memo raised (H2, the build path, the un-index risk, imported approvals). Three gaps can still show a wrong price, let a buyer pay for a bouquet no florist makes, or block a typo fix, so it is "approve once fixed".

## 2. Verdict: GO WITH FIXES
- **F1 (§2.3, §5.4, new AC after AC-7).** A price edited while a build runs is invalidated on the old container. The new deployment then serves the price it built with, for up to an hour (ISR 3600). Checkout's signed quote catches it at payment, but the page and `Offer.price` show the old price until then. Fix: the manifest records the build's data snapshot time. At boot, the new deployment calls `invalidate()` for every product and country whose rows changed after that time. AC: a price changed mid-build is in the edge HTML within 60 s of the new deployment going live. This applies to releases as well as publishes.
- **F2 (§2.6, AC-19, Q9).** One price change per day also stops a same-day typo fix on a bouquet you entered an hour ago. Fix: while a product has never been `active`, its price rows may be replaced freely, because no buyer has seen them. The supersede rule starts at the first `draft → active`. Add a T-19 case.
- **F3 (§2.5, §2.8, new AC).** Poland is already `live`, so the go-live preflight never runs for it. Spec 005's `availability()` counts any active florist mapping [inferred: spec 002 seeds three demo florists per country, and a seeded mapping may count]. Once `checkout.open` is on, a placeholder could be bought with no real florist to make it. Fix, as an AC: in production, a product is `saleable` only if a non-demo `active` florist can fulfil it in that country. Also make `goLivePreflight` runnable read-only on a live country, and show its result on `/admin/countries/PL`.

**Cuts that ship sooner (optional, your call):**
- **C1:** move task 8 (country editor and go-live) to after the first sale. Poland is live, so the first florist doesn't need it. Keep `dbCountryRegistry` in task 1.
- **C2:** drop the `vercel-hook` publish target. Vercel builds nothing today.
- **C3 (biggest, with a trade-off):** move the review ledger (task 2, ADR-0022) into slice B. Slice A would keep an Approve button that writes `reviewed_by`/`reviewed_at` through `withAdminContext` (so the audit trail records it), plus a trigger that clears `reviewed` when the text changes. The cost is weaker proof that no agent set a flag, and a second review migration later.
