# Spec 003 §14 A17: the 5 % unreviewed share counts only indexable surfaces

Subject: `specs/003-i18n-foundation.md` §14 A17 (Draft), PR #204. Advisor memo, 2026-10-05. Not legal advice.

## 1. In one sentence
A17 stops checkout, florist and admin English copy from switching the whole English site to `noindex`, and it fails safe (an unlisted key still counts), but its check looks at which file names a key, not at which page shows it, and one open question cannot be answered the way the text says.

## 2. Verdict: GO WITH FIXES
1. **§14 A17 clause 2, check 11: add a fifth fault, plus a seeded case in AC-41 and T-41.** Refuse any file under an entry's `paths` that is imported, directly or through other files, by a file under `src/app/[locale]/` outside every entry's `paths`, or by a shared file (the clause 2 list). Without it, a checkout component placed on a product page (a delivery-date picker, a cutoff line, a mini basket) shows `checkout.*` copy on an indexable page and check 11 still passes, because the key is named inside a checkout file.
2. **§14 A17 clause 7, Pointers: add spec 007.** Before the indexing flip, one CI check builds the indexable page set with every non-counted key's value swapped for a unique marker (for example `[[checkout.step.review]]`) and fails if any marker appears in the HTML. Markers avoid the "Back" noise the text worries about. This answers open item (d).
3. **§14 A17 open item (c): restate it.** "One word moves them" is not true. An `errors` entry needs `src/app/not-found.tsx` in its `paths`, and check 11's shared-file list refuses that file, so excluding `errors.*` takes an amendment. Say that, and keep `errors.*` counted.
4. **§14 A17 AC-43: add one list to the summary.** `i18n:check --summary` lists the buyer-facing keys under a scope entry that are still `reviewed: false`. The reviewer then reads a list for clause 5 instead of hunting for keys, and the same list can become the CI gate later (item b).

## 3. The four hats
**Building**
1. The check reads source text, not the import graph (clause 2; `usedKeys()` in `scripts/i18n-check.ts` L431). Fixed by fix 1.
2. Keys built at runtime (`` t(`checkout.${step}`) ``) are invisible to the scan [inferred from the regex rules at L404–L411]. Fix 2 catches them before anything is indexed.
3. Otherwise no concern: one small task, no caller changes, AC-3 unchanged, no conflict with ADR-0006 or ADR-0007.

**Google**
1. The only way this can leak is unreviewed text on an indexable page through an embedded component (fixes 1 and 2). Nothing is indexed before spec 007's flip (clause 4), so there is time.
2. Otherwise no concern. The rule removes a real risk: the first checkout PR would have emptied hreflang and the sitemaps for all English pages (clause 4).

**Law and compliance**
1. Clause 5 is enforced only by a reviewer reading a PR description. Checkout and buyer emails carry the total, VAT, delivery date and withdrawal wording, and the order confirmation must repeat the pre-contract information on a durable medium ([Directive 2011/83/EU Art. 8(7)](https://www.legislation.gov.uk/eudr/2011/83/article/8)). Fix 4 makes this checkable; a CI gate should come before the first real payment.
2. A demo checkout on the live site that looks real could mislead a visitor [inferred]. Reading it strictly (it ships) is the safe default.
3. Withdrawal and price-display wording needs a qualified lawyer's sign-off before real orders. Founder approval of the text is not the same thing.

**Customer**
No concern. Nothing a buyer sees changes; it keeps English pages findable.

### Recommended answers to A17's open items
- **(a) Demo checkout counts as shipping to buyers? Yes.** Real people can reach it, and you approve copy per batch anyway, so the cost is small.
- **(b) CI gate now? No, not yet.** Keep the reviewer check plus fix 4's list. Turn it into a blocking gate before the first real-money order.
- **(c) Count `errors.*`? Yes, keep them counted.** They are a handful of keys, approved once, and excluding them would break check 11's shared-file rule (fix 3).
- **(d) Source scan enough? Not on its own.** Use the scan plus fix 1's import rule now, and fix 2's marker check before indexing starts.

## 4. Questions the founder should ask
1. Does anyone other than me use the demo checkout on the live site today?
2. Am I happy to approve every checkout batch's exact text before its PR merges?
3. Will any checkout piece (date picker, cutoff line, basket) appear on product pages?
4. When is the first real-money order, so the CI gate in (b) is in place by then?
5. Which lawyer signs off the withdrawal and price wording, and when?

## 5. What looks right
Counting by default means any mistake leans toward `noindex`, never toward indexing unreviewed copy. Clause 5 states plainly that "not counted" never means "not reviewed".
