All destinations hub · [internal]
Purpose
The parent of every country page and the reason crawl depth from any locale home to any destination is two. It answers one question — where can we send flowers, and what is true about each of them today — and it is the only page that lists a destination we have no page for.
URL
/{locale}/{destinations}: /en/send-flowers-to · /en-gb/send-flowers-to · /de/blumen-verschicken · /pl/wyslij-kwiaty. The same localised segment the country page uses, from locales.data.ts.
Index
index,follow in a locale where at least one country page is indexable; otherwise noindex,follow and out of the sitemap — the same indexability() call, so the hub cannot be indexed into a page with nothing to link to. In Phase 0 that is en and en-gb; /de/blumen-verschicken and /pl/wyslij-kwiaty render, list every destination as text, and stay noindex until a human has written a guide in that language. Self-canonical; member of static.xml.
Reads
countries.ts — status, guidePublished, corridorPagePublished, the per-locale slug, citiesKey — plus destinations.* names and the same existence predicate the country page uses. Ordered with collator(locale) inside each group so Polish ł sorts where a Polish reader expects it.
States shown
region grouping · destination with a page (a link) · destination without a page (plain text plus one state line, never a link) · an empty region group · the whole-page empty state.
Not on this page
No price, no “tell us where to open next” email field (§13 Q4), no count of countries, no map, no flag image, no product.

Where we can send flowers

Seven countries in Europe, and we have written a guide to every one of them: what is given, what is never given, how an address is written, and which dates matter in a year there. We open a country only once we have chosen the florists ourselves, so the guide comes first and the delivery comes after it. Where we are not delivering yet, this page says so in the same words on every row.

No count of countries we do not serve, no map, no flags, no “over 140 destinations”. Seven, named.

No destination has a page in this localeThe page still exists and still renders: the <h1>, the intro, and one paragraph naming the seven destinations as plain text with the state line. It is noindex,follow and absent from the sitemap, because a hub with no page to link to is not a page worth indexing. It is not a 404: the URL is in the locale's navigation and a 404 there would be a broken site rather than an honest one.
