Florist inbox · list, order, photo · desktop 1440 · spec 011 · [internal]
Purpose
The florist's inbox v0: every order offered to the signed-in florist's shop, grouped by what it needs from them, then one order at a time with the one action its state allows. Built on the Phase 2 portal's foundations (spec 011 §2), so specs 026 and 027 extend these screens rather than replace them. Desktop: the same screens on the 12-column grid, list on columns 2 to 11, the order on 2 to 7 with the action card on 9 to 11.
URL
/demo/vendor-inbox (the list) · /demo/vendor-inbox/orders/{assignmentId} · /demo/vendor-inbox/orders/{assignmentId}/photo; every path from FLORIST_BASE_PATH (links on this artboard write it as {base}). No locale prefix. An id, never a name, in every URL.
Index
noindex (X-Robots-Tag), Cache-Control: private, no-store; 404 in production while signInPolicy("production") is empty (AC-22). robots.txt disallows /demo/.
Reads
listFloristAssignments(ctx) → FloristAssignmentListItemSchema; floristOrderView(ctx, assignmentId) → FloristOrderViewSchema, a union on the stage with no buyer field at all; the recipient's name, phone, address, note and card message exist only from acceptance to the photo (AC-25). Scoped by row-level security under requireFloristContext().
States
List: offers waiting with answer-by time · offer expired (text, no accept) · in progress · delivered · empty · the demo notice · the test-order control · refresh stopped after idle · menu open. Order: offer (no recipient contact) · declining (the five reasons, then “Decline the order”) · accepted, being made (recipient and card message shown, “Out for delivery”) · out for delivery (“Delivered, add the photo”) · delivered without photo (“Add the photo”) · photo received (recipient contact removed) · already answered · changed · offer expired · not found (404). Photo step: choose · chosen · wrong type · too large · sent.
Laptop band
1280 × 800: H1 46px at y 150, primary action (“Send a test order”) ends y 197 (in view) · 1470 × 830: H1 46px at y 150, primary action (“Send a test order”) ends y 197 (in view) · 1512 × 860: H1 46px at y 150, primary action (“Send a test order”) ends y 197 (in view) · 1512 × 945: H1 46px at y 150, primary action (“Send a test order”) ends y 197 (in view). Measured on this artboard rendered at each window size, annotation hidden (Playwright, 2026-10-05).
Actions
Each a no-JS form post to a florist command, offered only in the states order_transition allows (AC-29): Accept / Decline → respondToOffer (assignment.accepted / assignment.declined) · Out for delivery → markOutForDelivery (order.out_for_delivery) · Delivered, add the photo → markDelivered (order.delivered then order.photo_uploaded) · Add the photo → addDeliveryPhoto. All through spec 010's orderService.transition; none writes a status itself.
Refresh
A client island calls router.refresh() every 5 s while the list is visible and stops after 10 minutes without interaction, leaving the Refresh link (AC-26). No skeleton, no spinner: every page is a server render (spec 011 §5.3). Pending buttons use motion cell 3 of system/motion.dc.html; the photo fades in per cell 11.
Components
src/modules/partners/ui/inbox/: list group, list item, order head, facts list, recipient block, card message, decline reasons, photo field, the dock. Form primitives from system/components.dc.html “Forms” (file field, radio list, notice, field error).
Tokens
Ground --color-paper; items --color-card with --rule; answer-by --color-blush on --color-accent-strong; payout --color-leaf-wash; stage chips --color-sage-wash / --color-leaf-wash / --color-butter; the one primary action --color-accent; targets ≥ 56 px in the dock, ≥ 44 px everywhere.
Data drawn
Synthetic only: the recipient is tests/fixtures' “Anna Kowalska, ul. Marszałkowska 10/5, 00-001 Warszawa, +48 22 123 45 67”; products and tiers are catalogue rows. Payouts: “149 zł” is spec 011 §13 Q7's default (the founder accepted the defaults on 2026-10-04); every other payout is the Placeholder bar, because the seed payout mapping (TASK-026) does not exist yet. Times are in Europe/Warsaw, the destination's zone.

[slot · spec 011: the paused line]Refresh

Shown above the list once the island stops; the Refresh link reloads the page. Without JavaScript the link is always there.

Test-order control

Rendered only for members of a demo shop outside production (AC-33). It calls placeDemoOrder; the new offer appears within 5 s (AC-26).

Already answered

This order has already been answered.

A second Accept, or an answer from another device: the page shows the current state under this notice and writes no event (AC-27).

Changed since you opened it

This order has changed since you opened it.

A forged or stale post in a state order_transition does not allow: no event, the current page under this notice (AC-29).

Photo · chosen, before sending

IMG_2041.jpg3.2 MB

The native file input names the file; no client preview (no JavaScript needed). The photo is re-encoded on the server with every metadata field dropped (AC-30).

Photo · wrong type

This file is not a photo we can use. Please send a JPEG, PNG or WebP image.

A GIF or any file whose magic bytes are not JPEG, PNG or WebP; nothing is stored.

Photo · too large

This photo is too large. Please send one under 15 MB.

Over 15 MiB, refused while streaming; nothing is stored.

Order · not found (404)

[slot · spec 011: not found heading and line, with a link to Orders]

Another shop's order, or an id that does not exist: row-level security hides it, the answer is 404 (AC-23). Same page for both, so nothing leaks.
