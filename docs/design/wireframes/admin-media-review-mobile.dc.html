Admin · photo review · mobile 390 · spec 012b · [internal]
Purpose
One photo: look at it at full size, tick spec 006’s four checks, approve or reject (spec 012b §2.7, §2.4). Approval goes only through attest(), so the ledger names who approved which exact image. Phone: the photo first, then the checks and the buttons, then the provenance.
URL
/admin/media/{assetId}
Index
Never: X-Robots-Tag: noindex, nofollow and Cache-Control: no-store, private on every /admin response, <meta name="robots" content="noindex,nofollow">, Disallow: /admin/, no sitemap, no public link (spec 012 AC-5, AC-6; spec 012b AC-26). No locale prefix. Ids and SKUs, never names, in URLs.
Permission
media.review (admin, content) for Approve and Reject; without it the buttons are absent and the line says why.
Writes
attest(AttestInputSchema) with subject media_asset, the asset’s checksum_sha256 as value hash; review_write_guard() refuses any other way to set review_state (AC-10, AC-23). Reject needs a note. Tags: product:{id} and catalog:{iso2} for each product it is attached to, sitemap.
Rules
A pending or rejected photo cannot be main and renders no <img>. A florist’s photo cannot be approved while that florist has no terms_version (§13 Q11): Approve is absent and the line links to the florist. A photo renders in a language only with non-empty alt text that is not a file name, written on the product’s Photos tab.
States
Waiting with two of four checks ticked · approved · rejected with the note · florist without terms (no Approve) · imported, not re-read (approve again) · still making sizes · AI provenance.
