Admin · publish · desktop 1440 · spec 012b · [internal]
Purpose
The one place structural changes go out (spec 012b §2.3): what the database would add and remove against the live page list, per language, with the addresses; one Publish button; the run’s progress; and what failed. Desktop: one column, the live version on top, then what is waiting, then the history.
URL
/admin/publish
Index
Never: X-Robots-Tag: noindex, nofollow and Cache-Control: no-store, private on every /admin response, <meta name="robots" content="noindex,nofollow">, Disallow: /admin/, no sitemap, no public link (spec 012 AC-5, AC-6; spec 012b AC-26). No locale prefix. Ids and SKUs, never names, in URLs.
Permission
catalogue.publish (admin, content). Without it Publish is absent and the line says who can.
Reads / writes
existenceDiff() = the database’s URL set against the running manifest; GET /api/health’s commit and existenceHash. Publish creates one publish_run (PublishRequestSchema) and asks the publish target for one deploy of the tracked branch head: release in production, main in staging; never another commit. The catalogue.publish job polls once a minute; the new deployment marks the run verified only when its existenceHash and commit match (AC-7), then invalidate(['sitemap']) once and every added URL is requested once.
Target
Railway only (railwayTarget, an environment-scoped project token). No Vercel fallback: founder default to §13 Q16 C2. fake in tests; none in development and preview, where Publish is absent with the reason.
Guards
One open run per environment (a partial unique index); at most 10 a calendar day (§13 Q14); with catalogue.placeholder_window off, a removal list that holds an indexable URL is refused and names every one (AC-8). With the window on, removing placeholders is allowed.
States
Pending with counts and addresses · nothing to publish · asked · building (progress, announced politely) · deployed, checking · live and checked · failed with its code · timed out after 30 minutes · daily limit reached · removal of indexable pages refused · placeholders removed while the window is on · target none · backup warning.
Data drawn
Four added product pages per language: the synthetic florist bouquets FO-BQ-041 to 044 (045 has no approved photo, 046 is a draft) (slugs are the florist’s, so a slot). Commits a0e2943 and 523a3cc are real main commits used as examples; the page-list fingerprint, times and durations are test values. Product paths per language from src/config/locales.data.ts (product, produkt) and the country slugs from countries.ts.
Components
Admin shell, key-value list, data table, expandable address list (new, proposed), run progress steps (new, proposed), progress bar, banner, toast.
Tokens
Steps: done --color-stem, now --color-sky, failed --color-danger, to come --color-rule; added --color-stem +, removed --color-danger −.
Copy
[slot] copy Every string with a dotted underline is a [slot]: new wording, drawn as a proposal, not yet a key. Spec 012b §7 owns it: messages/admin/en.json under admin.catalogue, admin.media, admin.countries, admin.publish, admin.review; the founder approves the batch. Text without the underline is verbatim from messages/admin/en.json (admin.shell.*, admin.nav.*, admin.roles.*, admin.users.cancel), a registry, or the seed. A [bracketed] value is content we do not have yet (a florist’s bouquet name). Slice A adds no public message key (AC-27). Money through formatMoney in the admin’s en locale; times in the viewer’s admin_profile.time_zone with the zone named.
Scope
Slice A. Accepted defaults (founder 2026-10-20, “all defaults”): §13 Q16 C1 in part, so the country operations editor and the corridor flags are later (after the first sale) and are not drawn as editable here; C2, so Railway is the only publish target and there is no Vercel fallback; C3 declined, so approvals go through the ledger (attest()).
AC
spec 012b AC-5, AC-6, AC-7, AC-8, AC-38 (boot invalidation, not visible here), AC-26, AC-29
