Admin · florist detail · desktop 1440 · spec 012 · [internal]
Purpose
One florist: profile, terms, delivery zones, days off, products and payouts, and the status with what is still missing (spec 012 §2.5). Desktop: the record on two thirds; the status card sticky on the last third, so the next step is always in view.
URL
/admin/partners/{code}
Index
Never: X-Robots-Tag: noindex, nofollow and Cache-Control: no-store, private on every /admin response, <meta name="robots" content="noindex,nofollow">, Disallow: /admin/, no sitemap, no public link (AC-5, AC-6). No locale prefix. Ids, never names, in URLs.
Laptop band
1280 × 800: H1 32px at y 72, no primary action on this screen · 1470 × 830: H1 32px at y 72, no primary action on this screen · 1512 × 860: H1 32px at y 72, no primary action on this screen · 1512 × 945: H1 32px at y 72, no primary action on this screen. Measured on this artboard rendered at each window size, annotation hidden (Playwright, 2026-10-05).
Permission
partner.edit (profile, terms, zones, days off), partner.status (status) for admin and ops; partner.payout (products and payouts) for admin and finance. A section a role cannot change renders read only, with no buttons.
Writes
updatePartner (PartnerEditSchema: E.164 for the florist's country, AC-15), recordTerms, saveCoverage, saveBlackout, saveMapping (integer minor units + currency), setPartnerStatus after partnerStatusPreflight. Every form carries the row's updated_at; a save against a newer row changes nothing. All inside withAdminContext with an action, so the trigger audits them; the status change also passes the database's status-flip guard.
Status graph
onboarding → active | offboarded, active → paused | offboarded, paused → active | offboarded, demo → offboarded only. Only the moves the graph allows are buttons; Make active is absent, not disabled, until signed terms, a zone, a product with a payout and the channel's contact all exist, and the list says which are missing (spec 004 §14 A20; AC-16).
States
Onboarding with unmet conditions · all conditions met (Make active appears) · demo florist (Offboard only) · edit conflict · phone not E.164 · empty zones, days off and products.
Data drawn
Synthetic: the florist converted from the application on admin-applications-*; “149.00 zł” (entered as 14900 grosze) and the demo florist's 149 and 129 zł are example figures; real payouts come from the florist's agreed price (the seed's mapping, TASK-026, then admin).
Components
Admin shell, back link, form fields (36 px), select, data table, banner, status card with the condition list, buttons (one primary per screen: Make active, when present).
Tokens
Conditions: met --color-stem ✓, missing --color-danger × with the words; conflict banner --color-blush; Offboard --color-danger outline.
