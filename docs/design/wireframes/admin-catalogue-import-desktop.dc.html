Admin · catalogue import · desktop 1440 · spec 012b slice A.2 · [internal]
Purpose
One florist’s whole bouquet and price list from one CSV or Excel file (spec 012b §14, founder 2026-10-21: “also add option to bulk upload the product data in the cms too”; §13 Q17 to Q28 answered “bulk defaults”). Four steps: get the template or a florist’s current list; upload; check every row (new, changed, unchanged, error) with nothing saved; Apply all or nothing; then drop the photo files, matched by name. Desktop: dense tables in the spec 012 admin shell.
URL
/admin/catalogue/import (templates, upload, recent uploads) and /admin/catalogue/import/{id} (check, reasons, Apply, report; ?outcome= filters rows, ?page= pages by 100; ?step=photos the photo step). Handlers: GET /admin/api/catalogue/import/template?format=xlsx|csv[&florist=<code>] (attachment), POST /admin/api/catalogue/import (2 MB body), POST /admin/api/catalogue/import/{id}/photos (per file). Apply is a server action under withAdminContext({ action: 'catalogue.import.apply', reason }). Reached from the Catalogue page’s “Upload a price list” link (added to admin-products-*).
Index
Never: X-Robots-Tag: noindex, nofollow and Cache-Control: no-store, private on every /admin response and on the template, upload, Apply and photo handlers, <meta name="robots" content="noindex,nofollow">, Disallow: /admin/, no sitemap, no public link (spec 012 AC-5, AC-6; spec 012b AC-26, AC-47). No locale prefix. Import ids and SKUs, never a file name or a cell value, in a URL, a log line, Sentry or an audit request field (AC-47).
Permission
requirePermission('catalogue.edit') (admin, content) on both pages; without it, spec 012’s 403 (drawn in the band). No new permission: a row whose write needs price.edit, or catalogue.supplier with partner.payout, that the uploader lacks is a row error (AC-47). Copy and alt columns only in the uploader’s reviewer_locale grants (the founder: en, en-gb; AC-45).
Reads and writes
Upload: parseImportFile in memory (never to disk or R2), planImport over a read snapshot; writes only one catalogue_import row, previewed, with counts and plan hash (AC-42). Apply: one transaction, FOR UPDATE on the bouquets, plan recomputed and its hash compared, then createProduct/updateProduct, saveTier, saveMapping, saveCopy, replaceDraftPrice or supersedePrice; one invalidate() after commit with the union of the changed existing bouquets’ tags, none for drafts only (AC-43). Photos: uploadOriginal with every AC-22 rule, source = 'partner', supplier_partner_id = the row’s florist, licence = their terms_version, attached as main only where there is none, pending until attest() (AC-48). No import code makes an outbound request.
States
Upload page · empty · uploading and checking (polite live region) · file refused, every file-level message of AC-41 · check with errors, Apply absent with the reason · warnings waiting for a reason, Apply absent · ready, reasons typed, Apply present · applying · changed since the check (hash differs, nothing saved) · fault while saving (rolled back) · applied report · applied twice refused · expired after 24 hours (counts kept) · photo step with matched and refused files · photo rules refusal · photo step closed after the purge · 403.
Outcomes
Each data row has exactly one: New Changed Unchanged Error; a warning is drawn beside its row, not as an outcome. A changed row lists each field, old and new; a changed price shows both amounts (en and pl), the per cent and lowestPriceInLast30Days (AC-44). An error names its column and its rule id. Row numbers are the spreadsheet’s, header = row 1, and each is a row header (<th scope="row">, T-52).
Warnings
Soft rules need one reason per rule id per upload, listing the rows it covers, stored on the audit row of every entity it covers (§13 Q24, AC-47): price.change_over_30 on a bouquet on sale (on a draft a flag only), price.share_over_65, copy.reopens_approved naming the language (advisor F1).
Rule ids
Named by the spec: copy.formula_lead, copy.reopens_approved, price.change_over_30. Reused from the slice A artboards: tier.stem_count_odd, copy.slug_shape. Every other id drawn (price.parse, price.number_cell, price.share_over_65, price.below_payout, price.same_day, price.currency, import.formula_cell, import.duplicate_row, import.level_mismatch, copy.locale_not_granted, copy.slug_taken, copy.slug_locked, import.seed_sku, import.unknown_florist, import.permission, import.photo_ambiguous, import.photo_unmatched) is a proposal: task 5’s validators fix the ids, and the preview prints whatever id the shared function returns (AC-42).
Data drawn
Kwiaciarnia pod Lipą (pl-krk-pod-lipa, terms recorded, paid in PLN) and FO-BQ-041, 042 and 046 are the synthetic florist and bouquets of admin-products-* and admin-partner-detail-* (041 and 042 on sale, 046 a draft). FO-BQ-047 to 049 are three new synthetic bouquets, two sizes each (T-51’s founder path). Florist prices PLN 99.00, 149.00, 209.00 and the suggested prices PLN 179.00, 269.00, 379.00 are the slice A test values (÷ 0.60, + 8 % VAT, rounded up to …9). PLN 239.00 against PLN 149.00 is the 67.3 % share of admin-price-change-*. PLN 269.00 to 359.00 is +33.5 %. Photo file names are sample data. The uploaded file’s own name is never shown, stored or logged (AC-47), so no screen draws one.
Gap
Spec gap, drawn around: AC-44 says a blank price takes suggestedPrice; AC-45 says a blank cell on an update row leaves its field unchanged. For a size that already has a price in that country the two disagree. These artboards use a blank price only where there is no price yet (creates, and FO-BQ-046 with none), and a typed price on every changed price, so nothing drawn depends on the answer. The orchestrator raises it before /plan-tasks.
Components
Admin shell, data table, tabs with counts, banner, chips, card, check list, file drop, progress bar, empty block, photo card (all existing). New, proposed for system/components.dc.html “Admin”: the outcome tally, the row-error and row-warning lines with their rule id, the changed-field list (old struck through, new bold), the reason-per-rule panel, the file-match list.
Tokens
Error rows --color-blush with a --color-danger start edge; warned rows a --color-warning start edge; New --color-sage-wash; Changed --color-ink; Apply is the one poppy action, Upload and check the one on the upload page.
Copy
[slot] copy Every string with a dotted underline is a [slot]: new wording, drawn as a proposal, not yet a key. Spec 012b §14.11 owns it: messages/admin/en.json under admin.catalogue.import (the template’s instructions sheet reads the same keys); the founder approves the batch. Text without the underline is verbatim from messages/admin/en.json (admin.shell.*, admin.nav.*, admin.users.cancel, admin.errors.*), a registry, or the seed. A [bracketed] value is content we do not have (a florist’s bouquet name, so also the address made from it). Typed reasons are sample input, not copy. Slice A.2 adds no public message key (AC-27). Money through formatMoney in en and the country’s locale; times through format.ts in the viewer’s admin_profile.time_zone with the zone named.
Scope
Slice A.2, after slice A’s tasks 5 to 7. Defaults: all or nothing (Q18); one sheet, one row per bouquet, size and country (Q19); blank selling price takes the suggested price (Q20); photos by file name after Apply, never URLs (Q21); only granted languages (Q22); never on or off sale, never deletes, blank never clears (Q23); placeholders untouchable (Q26); a florist’s current list as a file (Q27); this address (Q28).

spec 012b AC-40 to AC-48; AC-12, AC-15, AC-16, AC-22, AC-23 through the shared rules; T-51, T-52, T-53
