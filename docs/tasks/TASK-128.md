## Binding

**Owned: spec 009 AC-15 and AC-24 (T-15, T-24).** The JS-off half of AC-13 (the form that works with no script) is *built* here and *asserted* in TASK-129's T-13; the row says so. Spec 009 §14 **A10** rewrites the clauses below, and A10 wins over §5.2 and the original AC text.

- **The product route never reads the query string** (A10). The route file `src/app/[locale]/[segment]/[child]/[grandchild]/page.tsx` reads no `searchParams` and stays prebuilt (A6: every (locale, published country, product) is emitted, `dynamicParams` inert under the locale gate). Putting `searchParams` back turns the product route per-request in the build output, and T-15 must go red on that.
- **The form** (A10). The JS-off form stays `method="get"` and submits to the bare product URL. A `next.config` `beforeFiles` rewrite of spec 008 §14 A13's kind, one rule per (locale, key), keys `tier` and `date`, sources built from the locale registry's `product` segment, each with a `has: query` condition, sends it to an internal parameter route under the same `_query` segment. Rules hold parameter names only. Next matches sources case-insensitively, so the parameter route answers **404 unless the original path is exactly the canonical lowercase one** (`/EN/poland/product/{slug}?tier=x` and `/en/poland/PRODUCT/{slug}?tier=x` both 404). A direct request for the internal path with neither key answers 404.
- **AC-15 as A10 restates it.** "the internal parameter route alone parses `?tier=` / `?date=`, strictly. A valid value re-renders the selection. An unknown tier, a malformed date, an out-of-window date or an unselectable date falls back to the default rendering with a 200 and no error. Every URL that carries `tier` or `date` is `noindex,follow` with a canonical to the bare URL. A URL that carries only unknown parameters is served the prebuilt bare page, whose canonical is the bare URL. No parameterised URL appears in a sitemap or as an `<a href>` anywhere on the site." A URL with only `utm_*`, `gclid` or `fbclid` matches no rule and is **not** `noindex` (supersedes §5.2 L167). An unknown parameter beside `tier`/`date` is dropped by the strict schema.
- **One render path.** The parameter route renders through the same `productView()` and the same page module as the bare route. `productView()` takes `parameterised` as a **required** field (TASK-125 carry-forward): `false` on the bare render, the real value here. The page may not call `priceProjection`, `dateSurcharges`, `deliveryWindow` or `productPageIndexability` itself (`tests/unit/catalog-product-view-source.test.ts`). Robots comes from the engine's `unparameterised` term, never a `noindex` literal outside `modules/seo` (spec 009 §6).
- **AC-24.** "PDP responses carry no `Vary` and no `Set-Cookie` and are byte-identical with and without `fo_locale`, `fo_currency` and `fo_consent`; the bare URL is ISR with `revalidate` 3600 (300 when live) and the tags of §5.4; `src/lib/cache.ts` is the only invalidation path; parameterised responses carry the shared-cache header of 008 §5.4" (`public, s-maxage=3600, stale-while-revalidate=86400`, a `next.config` `headers()` rule beside `src/lib/listing-cache-headers.ts`, keyed from the same registry, on the address the visitor asked for). Per A10 "(300 when live)" is a **pure policy keyed on `pickerState()`**: `unavailable` and `preview` get 3600 with §5.4's tags (`product:{sku}`, `catalog:{iso2}`, `catalog:{iso2}:{locale}`, `sitemap`); `live` gets 300 plus `cutoff:{iso2}`. Extend `urlsForTag()` in `src/lib/cache.ts` to the product tags. The route's own live 300 s revalidation and the purge at cutoff time belong to the task that makes the first country live, not this one.
- **Phase 0 tier change** (A10, memo E-3). In `unavailable` and `preview` changing the tier is JavaScript-only; every tier's price is already printed. AC-13's JS-off clause binds the `live` state, and T-13's JS-off half runs on the `live` fixture. The picker's "Use this date" button renders only in `live` and only when a date is selectable (TASK-126).
- **robots.txt.** The row says "parameter shapes per spec 007 §14 A5". A5 reads the Disallow clause as **sort parameters only**, and spec 009 §6 says the shapes are added "without blocking them, so their `noindex` can be seen". Default reading, binding unless the reviewer rules otherwise: **no `Disallow` for `tier` or `date`** (a Disallow would hide the `noindex`). Pin it as fixtures in `tests/fixtures/seo/robots/plan-02-disallow.json` (a `?tier=` and a `?date=` URL, each allowed, plus a combined `?tier=x&sort=price-asc` case that stays disallowed by the sort rule).
