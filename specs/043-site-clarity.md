## 1. Problem

The founder, 2026-10-20, in chat, verbatim: "the website seems a bit confusing, so a few pages and everything. So fix that up." The orchestrator walked the live site (flowersoverseas.com, release 770c63a4, `noindex`) and listed twelve findings (C1 to C12, work order `wo-spec-043`). The spec writer re-checked each on the live pages and in the code on 2026-10-20; §1.1 records what holds.

The site makes a visitor answer three questions before it answers theirs: **which country am I shopping for, can I order, and why did the prices just vanish?** The header mixes three browse models (a country shop, country-less category hubs with no prices, country-less occasion hubs with no prices), so one click from a priced Poland page lands on a price-less page that asks for the destination again. The ordering state is said two or three times per page in different words ("Guide · not delivering yet", "P.S. Ordering opens soon", "(not yet)"), seven times in a row on the destinations block, and some public lines read like notes to ourselves ("Our picks until real orders start.", "Photography to supply"). Ranking stays priority 1 (`CLAUDE.md`): every fix keeps every indexable hub, URL, canonical, sitemap and hreflang as it is.

## 2. Scope

- **A. The header knows the destination from the URL.** On a page whose URL names a destination with a shop, the header's shop items (Our selection, Bouquets, Roses, Plants, Birthday, Sympathy) link to that destination's own priced pages, in the server HTML, per URL, the same for every visitor. Everywhere else they link exactly where they do today.
- **B. One head for every country listing.** Under the H1, one destination line ("Where is it going? Poland · change destination", reviewed keys) whose link leads to the hub of the same thing; one ordering-state line; no "P.S." mark, no state eyebrow.
- **C. The state said once per block.** The home's Destinations block and the destinations hub print the shared state once when every destination shares it.
- **D. Can I order? on the home's first screen.** While no destination takes orders, the not-open state text sits in the first viewport beside the sentence form.
- **E. Chips grouped by kind.** On the shop root, and inside the country category's "Categories" disclosure, the chips for what it is come first and the occasion chips follow, each group under a reviewed heading.
- **F. No empty boxes up front, no internal caption.** In every product list, products with an approved photograph come before products without one; a placeholder box carries no words; every card of a grid is visible after a real scroll and when printed.
- **G. Copy that sounds like a shop.** The home row heading, the count line's noun, the destinations hub intro, and the occasions index caption at every width (§7 table).
- **H. No eyebrow repeats the trail.** No eyebrow on a listing or hub page equals a label of that page's breadcrumb.

## 4. User stories

- As a **buyer on a Poland page**, when I click Roses in the header I see Poland's roses with prices, so I never lose the country I chose.
- As a **buyer**, I see once, in plain words, whether I can order and that every price is the price I pay, so I do not read the same warning three times.
- As a **buyer on the home**, I learn in the first screen that ordering opens soon, before I fill the sentence in.
- As a **buyer on a country page**, I can see which country I am shopping for and change it in one click, and the change takes me to the same kind of flowers for another country.
- As a **buyer scanning the shop**, I find "what it is" and "what it is for" as two short groups instead of one list of twenty.
- As **Googlebot**, I find the same hubs, URLs, canonicals, sitemaps and hreflang as before, every link answers 200, and every document is the same for every visitor.
- As the **founder**, I approve one short copy list, and the public site stops sounding like a draft.

## 5. Design

### 5.1 Data model changes

None. No table, column, migration or rollback. Everything reads existing data: the destination in the URL, `listingExists()`, the hub destination rows `listingView()` already builds, `categories.json`'s `kind`, `media_asset.review_state`, `deliveryDatesOpen()` / `anyDeliveryDatesOpen()`.

### 5.2 API / server actions / jobs / events

No route, action, job or event. Two pure functions in `src/modules/catalog`, exported from its barrel, zod-free (inputs are already parsed views):

- `destinationShopLinks(locale, iso2): Promise<ShopNavLinks | undefined>` — for each header shop item, the href in destination `iso2`, or `undefined` when the destination has no shop root in `locale`. The rule (one source of truth with the hubs):
  - Our selection → the destination's shop root.
  - Bouquets, Roses, Plants (category hubs `bouquet`, `roses`, `plant`) → the href that category hub's own destination list gives for `iso2`; else the shop root.
  - Birthday, Sympathy (occasion hubs) → the href that occasion hub's own destination list gives for `iso2`; else the shop root.
  - Occasions, Destinations → not in the result (unchanged everywhere).
- `photoFirst<T extends { photo: { kind: string } }>(items: readonly T[]): T[]` — a stable partition: items whose photo is an approved asset first, in input order, then the rest, in input order.

`ShopNavLinks` is a plain record keyed by the `categories.ts` row id. No new zod schema crosses a boundary.

### 5.3 UI

The `/design` pass draws every state below at 1440 × 900 and 390 × 844 before `/plan-tasks` (§12).

**A. The header (C2).**
- **Country context.** A page is in the context of destination X when its URL carries X's slug: the country shop root, a country category, a country occasion, a product page, and X's guide (`/{locale}/{destinations}/{x}`). Checkout, tracking, info and legal pages carry no context.
- **In context, with a shop root for X in that locale:** the six shop items link as `destinationShopLinks()` says, on the desktop row and in the phone Menu. Labels, order, styles, Occasions, Destinations and Send flowers are unchanged.
- **Out of context, or no shop root:** every item links exactly as today (`site-links.ts`; Our selection to `DEMO_DESTINATION_ISO2`'s shop root).
- **How it stays static.** The row is resolved per route without reading request headers, cookies or the client path, in the way the `@notice` and `@switcher` parallel-route slots already do (`src/app/[locale]/layout.tsx` L193 to L204). No client JavaScript is added. The mechanism is the implementer's within these constraints. **No stale row on a client navigation:** if the row is a parallel-route slot, that slot has a page (or a catch-all) for every route under `[locale]`, so its content always comes from the route being shown. Next.js keeps an unmatched slot's previous content on a client-side navigation and uses `default.tsx` only on a full load (Next.js parallel-routes docs). Every public link is a plain `<a>` today, but one future `next/link` would otherwise leave a Poland row on the home (AC-3, T-03).
- No item ever links to a URL that is not 200 (spec 004 AC-14).

**B. The country listing head (C1, C4, C10).** On the shop root, the country category and the country occasion page, every page number:
- Breadcrumb (unchanged), H1 (unchanged).
- **The destination line**, directly under the H1: `product.destination.label` ("Where is it going?"), the country name, and `product.destination.change` ("change destination") as a link. Its target is the hub whose own destination list links this page (the inverse of A's mapping): a category hub before an occasion hub where both do; the destinations hub where none does, and always on the shop root. Same component and look as the product page's destination control (spec 009), drawn by `/design` for the listing.
- **One state line, page 1 only.** While ordering is not open in X (`deliveryDatesOpen(X)` false): `shop.root.demoNotice` ("Ordering opens soon. Every price here is the price you will pay, with VAT and delivery included."), as plain text. No separate state eyebrow, no `shop.note.mark` ("P.S."), no `shop.note.label`. While ordering is open: `shop.root.priceLine` ("Every price includes VAT and delivery.") and no demo notice. No listing renders `destinations.state.*` (§14 A-founder-2026-10-22 item 1). (amended by §14 A-founder-2026-10-22)
- On a phone the country occasion page keeps the note's place after the grid (spec 008 §14 A-founder-2026-10-18c), without the mark.
- The occasion hub's `shop.hub.noMoney` sentence renders once, as plain text, without the "P.S." mark.

**C. The destinations block (C11).** On the home's Destinations block and on the destinations hub: when every listed destination has the same state, the state text renders once, as the block's caption, and no row carries it. When states differ (a destination opens), each row carries its own, as spec 007 AC-33 says.

**D. The home's first screen (C1).** While `anyDeliveryDatesOpen()` is false, the not-open state text (the key TASK-239 sets to "Ordering opens soon") renders as one line inside the hero's sentence section, visible in the first viewport at 1440 × 900 and 390 × 844.
