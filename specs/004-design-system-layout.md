## 1. Problem

Spec 003 left the site *correct* and *unlookable*. Four locale URLs render with the right `lang`/`dir`, a localised `<title>` and a crawlable `/` chooser, but every document is semantic markup with one `underline` class on it: no colour, no type, no spacing, no header, no footer, no trust layer, and no consent banner. `plan/09` reserves 22–28 Sep 2026 for "`004` design system + layout (tokens, logical CSS, header/footer, trust strip, consent banner, banner)", and three of Phase 0's nine acceptance criteria are unreachable without it: AC 2 (Lighthouse mobile ≥95 with LCP <2.0 s in all four locales), AC 6 (zero fabricated reviews or demo partners on any page — a rule about what the layout is *allowed* to render) and AC 7 (consent banner functional, Consent Mode v2 default-denied, GA4 receiving cookieless pings).

It is also the last cheap moment. Specs 005–011 add a catalogue, corridor pages, category grids, a PDP, a checkout and an admin — every one of them a consumer of tokens, layout primitives, the header, the footer and the trust components. A design system written after them is a refactor of six specs; written now it is the thing they are built against. The same holds for the two gates spec 001 deliberately deferred to this spec and recorded in `docs/architecture.md` §4: the **Content-Security-Policy** (deferred because "the shell loads no script beyond the Next runtime and no third-party origin except Vercel's own preview-feedback script"), and the **Lighthouse job's `continue-on-error: true`** (`ci.yml` line 945: "004 ships the design system — hence `continue-on-error: true` on the job … Spec 004 removes `continue-on-error`"). Both are lifted here or they rot.

Four constraints shape the design more than any of the plan documents do.

**No database, no domain, nothing indexable, no founder provisioning.** Spec 002 is parked (TASK-013 `blocked`), so there is no `country`, no `partner`, no `review`, no `consent_log` and no image in object storage. There is no custom domain and no GA4 measurement id. ADR-0007 keeps everything `noindex` with `Disallow: /` until spec 007. So this spec ships a layout that is honest with **no data at all**: every element that would normally be filled by a row — destination list, florist count, review score, payment logos, company registry number, legal links, product imagery — is either declared as config with a published/unpublished flag and an empty state, or is not rendered. §2 makes that the mechanism, §6 makes "zero links to a non-200 URL" an acceptance criterion, and §8 makes "nothing claimed that we cannot show" a compliance criterion rather than a good intention.

**The client-JS budget is already blown.** `plan/01` §7 caps JS on indexable pages at 120 KB gzipped; the Lighthouse job measures 304 KB of script on `/` today and a performance score of 0.88–0.93 against a 0.95 gate. Roughly 76% of it is the browser Sentry SDK (~146 KB gz) plus zod (~84 KB gz), pulled into every page by `instrumentation-client.ts` → `sentry.client.config.ts` → `@/lib/sentry` → `./logger` → zod. Spec 003's TASK-043 may fix it; if it has not merged when 004 starts, **this spec fixes it in its first task** (§2, §12), because a design system that adds a font, a header, a footer, two client islands and eventually a GA4 tag on top of a 2.5× budget overrun cannot be measured at all. The budget headroom is a designed artefact here, not a hope: §11 carries a bundle table.

**A nonce cannot live in cached HTML.** `plan/01` §9 says "Content Security Policy with nonces for GA4 and payment iframes". A nonce must be unique per response; an ISR/SSG page is one cached response served to everyone, so a nonce baked into it is a public constant and `'strict-dynamic'` built on it is theatre — and generating one per request means rendering every indexable page dynamically, which is a direct hit on priority #1 and #2. This spec therefore splits the policy by render mode (§5.2) and proposes ADR-0016 rather than quietly contradicting the plan (§13 Q5).

**Four open founder decisions, all with defaults.** A9 (brand assets) default is "spec 004 creates a minimal token system" — accepted, and §5.3 says what "minimal" means. A6 (guarantee name and terms) default is "7-day freshness, redeliver-or-refund" — accepted as *copy*, so a rename is a message-catalogue edit and not a code change. A2 (homepage country pick → corridor page) default accepted, and the picker's targets are data. A7 (six guide destinations: DE, FR, ES, IT, RO, NL) default accepted, and the destination list is data. All four are asked in §13; none of them blocks implementation, which is the point of writing them down as data.

## 2. Scope

Each bullet is testable; §9 names the AC.

**Where the design system lives (read this first)**

- A new module, **`src/modules/ui/`**, owned by this spec: tokens documentation, layout primitives, header, footer, trust strip, consent banner, icons, the image wrapper. `plan/01` §5's module list is domain-shaped and has no home for a design system, and `app/` must stay "routes only; thin" while the header and footer are rendered by every route group — so this is a **documented addition** to the module list, not a violation of the boundary rule (§12; §13 Q9 offers `src/components/` as the alternative). It obeys every existing rule: a public `index.ts` barrel, no deep imports, `app/` imports from it and never the reverse, registered in the same PR in `docs/architecture.md` §3 and the `MODULES` manifest of `scripts/check-layout.ts`.
- Tokens are **CSS custom properties declared in a Tailwind v4 `@theme` block** in `src/app/globals.css` (plus `@layer base` resets and `@utility` definitions). There is no `tailwind.config.js` in v4 and none is added. A component never sees a raw colour, size or duration: it uses the generated utilities.
- **Everything data-gated is config, projected for spec 002.** `src/config/countries.ts` (Phase-0 destination list: ISO code, per-locale slug from `plan/02` §4.1, name message key, `corridorPagePublished: false`), `src/config/site-links.ts` (every header/footer link target with the spec that publishes it and a `published` flag), `src/config/company.ts` (legal identity with a `registered: false` state), `src/config/cookies.ts` (the cookie register). Each follows spec 003's precedent exactly: zod-parsed at module load, no database import (`pnpm check:no-db` covers the new files), and a `toCountryRow()`-style projection where spec 002 owns the eventual table, with a unit test pinning the column set so the two cannot drift. `docs/architecture.md` §2 already reserves `countries.ts` for "002/004".

**Tokens (`plan/01` §7, `plan/07` §8, A9 default)**

- **Colour** as *semantic* tokens over a small primitive ramp: `--color-surface`, `--color-surface-raised`, `--color-surface-muted`, `--color-ink`, `--color-ink-muted`, `--color-brand`, `--color-on-brand`, `--color-accent`, `--color-on-accent`, `--color-border`, `--color-border-strong`, `--color-focus`, `--color-success|warning|danger` with their `--color-on-*` partners. Palette intent per `plan/10` §3's locked imagery style guide so the chrome does not fight the photography: a warm neutral-grey ramp (9 steps) as surface and ink, one deep botanical green as brand, one warm blush/terracotta as accent. Exact hex values are the implementer's, subject to the contrast test below, and live in **one** file so a founder swap is one diff.
- **A declared contrast manifest, unit-tested.** `src/modules/ui/tokens/contrast.ts` lists every foreground/background pair a component is allowed to use; a unit test computes the WCAG 2.1 relative-contrast ratio for each and fails below 4.5:1 for body text, 3:1 for ≥24 px or ≥19 px bold text, and 3:1 for UI component boundaries and focus indicators. Adding a component that needs a new pair means adding it to the manifest, which means passing the test. This is `plan/07` §8's "design tokens with contrast-checked palette" as a gate rather than a promise.
- **Type scale**: one variable font, seven steps (`--text-xs` … `--text-4xl`) with `clamp()` fluid sizing, paired line heights and letter-spacing, and a `--measure` (max line length) token. **Spacing**: 4 px base, 9 steps. **Radii**: 4 steps + `--radius-full`. **Shadows**: 3 steps. **Motion**: `--duration-fast|base|slow` and two easings. **Layers**: a named `z-index` scale (`--layer-header`, `--layer-banner`, `--layer-overlay`) so a sticky header, the suggestion banner and the consent sheet cannot fight (they are three of the four elements that overlap in this spec). **Breakpoints and container widths** stay Tailwind's defaults plus a `--container-prose`.
- **No dark mode in Phase 0** (§13 Q3). `color-scheme: light` is declared explicitly so form controls and scrollbars do not render dark on a light page, and because the token names are semantic, adding a `@media (prefers-color-scheme: dark)` override later is one block in one file and zero component edits. What is rejected is *shipping* it now: it doubles the contrast matrix and every visual baseline for a demo whose job is to sign three Warsaw florists.
- **`fo/no-raw-color`** (new ESLint rule, fixture pairs + RuleTester tests in the spec 001 style): bans arbitrary-value colour utilities (`bg-[#…]`, `text-[rgb(…)]`, `border-[hsl(…)]`, `shadow-[…rgba…]`) and hex/`rgb()`/`hsl()` literals in `className` anywhere in `src/` outside `src/app/globals.css`. Stylelint gains `color-no-hex` and `declaration-property-value-disallowed-list` entries for the same reason, scoped to exclude the `@theme` block. This is the token analogue of `fo/no-physical-css`: one place to change a colour.

**Font (`plan/01` §7: "1 variable font, `font-display: swap`, subset per script")**

- One self-hosted variable font, **Latin + Latin-Ext subsets** (Latin-Ext is non-negotiable: `ą ć ę ł ń ó ś ź ż` for `pl` and the `ro`/`tr` diacritics of Phase 4), weight axis subset to the range actually used, loaded through `next/font/local` from files committed under the repo (no Google Fonts request at runtime — a self-host is both a CWV and a German-court-risk decision, `plan/07` §1.4). Recommended face: **Inter Variable** (SIL OFL, complete Latin-Ext, well-behaved fallback metrics); §13 Q2 asks the founder to confirm or name another.
- `font-display: swap`, `preload` on the subset the locale needs, `adjustFontFallback` (or an explicit `size-adjust`/`ascent-override` fallback stack) so the swap costs no layout shift. Budget: ≤45 KB total font transfer per page, asserted from the build output; no second display face in Phase 0.

**Logical CSS and RTL readiness (`plan/03` §4)**

- Logical utilities only, as spec 001's `fo/no-physical-css` and Stylelint config already enforce; every primitive and component in this spec is written in `ms-/me-/ps-/pe-/start-/end-/text-start` form, and the enforcement is now exercised by real layout rather than by fixtures.
- **`@utility mirror-in-rtl`**: `[dir="rtl"] &{ transform: scaleX(-1) }`, applied to direction-carrying icons (arrow, chevron) and never to the wordmark, a clock, a check or a logo. The icon set ships with the mirroring intent encoded per icon, not decided per call site, so a call site cannot get it wrong.
- The `ar-XB` pseudo-locale visual project (spec 003 TASK-042) becomes a real gate here: for the first time there is a layout for it to mirror, which is exactly the `/review 8` note that "the two visual baselines are byte-identical blanks today".
- The `<bdi>` rule spec 003's runbook records is honoured by the first component that renders user-supplied text — there is none in 004, so the rule is carried into `docs/runbooks/design-system.md` for 009/010.

**Layout primitives and chrome (`plan/04` §3, §15)**

- Primitives: `Container` (max width + inline padding + `--measure` variant), `Stack` (vertical rhythm from the spacing scale), `Row`/`Cluster` (inline with wrap and gap), `Grid` (2-up mobile, 4-up desktop — the card grid 008 will use), `VisuallyHidden`, `SkipLink`. No component ships a bespoke margin: spacing comes from the parent primitive, which is what stops six later specs from inventing six vertical rhythms.
- **Header**: 56 px on mobile, sticky, no CLS (fixed height reserved, not measured after paint); wordmark/logo linking to the locale home (an inline SVG committed to the repo, drawn from A9's default "minimal system" — a typographic wordmark, not an illustrative logo the founder has not approved); primary nav rendered **from `site-links.ts`, only for published targets** (in Phase 0: nothing, so the mobile header is wordmark + locale switcher + currency chip, and the desktop nav appears item by item as 007/008/011 publish pages); the spec 003 `LocaleSwitcher` restyled in place; a **currency chip** that is text only — the locale's default currency ISO code with an `aria-label` from a message key ("Prices shown in {currency}"), server-rendered, identical for every visitor, because the currency *menu* and the `fo_currency` write are spec 008's and must not vary cached HTML (`plan/03` §1, spec 003 §3). Tap targets ≥44 px; no hover-only affordance.
- **Footer**: legal and info links from `site-links.ts` (published only), with the localised paths already fixed in `src/config/locales.ts` reserved as unpublished targets — `/de/impressum`, `/de/rechtliches/agb`, `/pl/regulamin`, `/{loc}/legal/*`; a **company identity block** from `company.ts` that renders the trading name and contact channel now and adds registry code, address and VAT id only when `registered: true` (the OÜ does not exist yet: `plan/09` targets 1 Nov, and inventing a registry number is a `plan/07` §6 offence, not a placeholder); a **`TrustMarks` slot with an explicit empty state** — no payment logos (no live method, and the logos are third-party trademarks), no Trustpilot badge, no review count, no star rating, nothing hidden-until-≥25-reviews because there is nothing to hide (Phase 0 AC 6); and a **"Cookie settings"** control that re-opens the consent banner (`plan/04` §11 requires it to be re-openable from the footer).
- **Trust strip**: server-rendered text, three claims only, each true today — the guarantee (A6 default: "7-day freshness guarantee · redeliver or refund"), "Hand-made by a local florist", "Price includes delivery and VAT" (`plan/04` §3, §12; `plan/07` §4). No Trustpilot line, no delivery-photo claim on a page with no photos, no florist count with no florists. Rendered on the locale home in 004; 008/009 mount the same component on shop pages.
- **404 and 500** documents styled (they exist and are localised from spec 003); the `/` chooser styled; the **skip link** given a visible focused state; a global `:focus-visible` ring from `--color-focus` that meets 3:1 against both adjacent surfaces; `@media (prefers-reduced-motion: reduce)` disabling every transition and animation the tokens allow.

**Locale-home skeleton (`plan/04` §4, A2 default)**

- Above the fold: `H1` (the **LCP element in Phase 0 is text**, because 006 has not generated any imagery yet — see below), a one-sentence proposition, and the **destination picker**. Below: "How it works" in three steps (You choose → a vetted local florist makes it → photo on delivery), the trust strip, and nothing else. No best-sellers (no catalogue), no occasion module (no calendar data), no delivery-photo gallery (no photos), no reviews carousel (Phase 0 AC 6), no "For florists" teaser until 011 publishes the page.
- The **picker** is server-rendered and usable before hydration (`plan/04` §4): a labelled list of the seven Phase-0 destinations from `countries.ts` in the locale's collation order (`collator(locale)` from spec 003). Each destination whose `corridorPagePublished` is `true` renders as a link to `localePath(locale, "corridorCountry", slug)` — A2's default target, the corridor page; each unpublished destination renders as plain text with a state message ("we are onboarding florists here"). In Phase 0 every flag is `false`, so the picker links nowhere and the site has **zero internal links to a non-200 URL** (AC-14); spec 007 flips flags and the picker becomes navigation with no markup change. Combobox/typeahead enhancement is 007's.
- A **hero media slot** is reserved with a fixed aspect ratio and a token-gradient placeholder, so that when 006 lands imagery the LCP element changes from text to image with **no layout shift and no template edit**. The slot renders no `<img>` in Phase 0 (`plan/10` §3's honesty rule: the demo shows no image it does not have).

**Image conventions (`plan/01` §6, ADR-0014, ADR-0015)**

- `src/modules/ui/media/`: a thin `Media` wrapper over `next/image` fixing the conventions once — `sizes` per named slot (hero 100vw, grid 50vw/33vw/25vw, thumb 96 px), fixed aspect-ratio boxes, `loading="lazy"` + `decoding="async"` below the fold, exactly one `priority` candidate per page (asserted by a lint-free convention check in the gallery test), and `alt` **required** as a prop with no default, because alt text is per-locale data in `product_media` and is never generated at render.
- The **R2 loader seam** of ADR-0015: `src/modules/ui/media/loader.ts` exporting a `next/image` custom loader behind an interface, with a `placeholderLoader` in Phase 0 (no bucket exists) and the R2/variant loader arriving with 002/006 as a swap inside the module — the same seam shape spec 003 used for the locale registry, so no call site changes.

**Consent (`plan/04` §11, `plan/07` §5, Phase 0 AC 7)**

- **Built, not bought** (`plan/07` §5's recommendation, confirmed here; §13 Q6). `src/config/cookies.ts` is the **cookie register**: every cookie we set or intend to set, with name, category (`essential | analytics | marketing`), purpose message key, lifetime, first/third party and the spec that introduces it. Phase 0 rows: `fo_locale` (essential, 365 d, spec 003), `fo_consent` (essential, 6 months on reject / 12 months on accept, this spec), plus the declared-but-not-yet-set `fo_session`, `fo_csrf`, `fo_currency`, `fo_basket` and the GA4/Stripe rows marked "not set in Phase 0". This one file feeds the banner's settings panel, the cookie-policy page 007 will render, the RoPA, and the reviewer's check that no cookie exists outside the register (AC-22).
- **Consent Mode v2, default denied, before anything loads**: a tiny inline `dataLayer`/`gtag` bootstrap setting `ad_storage`, `ad_user_data`, `ad_personalization`, `analytics_storage` (and `functionality_storage`, `personalization_storage`, `security_storage` where honest) to `denied`, `url_passthrough: false`, `wait_for_update` set. It is the only inline script in the app and it is ≤1 KB, which is what makes the CSP conversation in §5.2 concrete.
- **Banner**: bottom sheet on mobile, non-blocking, non-modal, focus not stolen, `Esc`-dismissible, **Accept all / Reject all / Settings as three equal-weight controls** (same size, same contrast, same prominence — no dark patterns, `plan/07` §5), no pre-ticked non-essential box, categories disclosed inline from the register (so the disclosure is complete even before a cookie-policy page exists), reserving no layout space (overlay → CLS delta 0) and re-openable from the footer. Choice persisted in `fo_consent` (first-party, `Path=/`, `SameSite=Lax`, `Secure` outside dev, not `HttpOnly`, JSON-encoded `{v: policyVersion, a: bool, m: bool, ts}` and an unlinkable random `cid`), 6 months for reject / 12 months for accept, written **only on an explicit user action** and never by the server on a cached page (no `Set-Cookie` on any cached response, preserving spec 001 AC-15 and spec 003 AC-12).
- **`ConsentDecision` zod schema + a `ConsentSink` seam**: `POST /api/consent` (`plan/05` #65) validates and hands the decision to a sink. Phase 0 ships `logConsentSink` (one structured log line: `cid`, timestamp, categories, policy version — no IP, no user agent, no page URL, no PII); the durable `consent_log` table of `plan/07` §5 arrives with spec 002 as a second implementation behind the same interface. A forged or unparsable `fo_consent` value is treated as *no consent* and rewritten.
- **GA4 wiring, staged so it needs no founder action to be implemented or tested**: the tag loader is present and reads `NEXT_PUBLIC_GA4_MEASUREMENT_ID`. Unset (Phase 0 CI, local, preview) → no third-party script at all, and a test asserts zero requests to `googletagmanager.com`. Set → the tag loads *after* the Consent Mode default block, sends cookieless pings under default-denied, and calls `gtag('consent','update',…)` when the user accepts. So `plan/09` Phase 0 AC 7 becomes true the moment the founder pastes the id from the week-1 GA4 property into the env store, with **zero code change** — and the event plan, the `consent_state` dimension and the server-side `purchase` event stay spec 023's (§3, §13 Q7).

**Component gallery (`/dev/components`) — decided, not asked**

- A single server-rendered route, `src/app/(dev)/dev/components/page.tsx`, x-default document, `noindex`, rendering every token ramp and every component in every state (default/hover-equivalent/focus/disabled/empty/error). Present only when `ENABLE_DEV_UI` is true; the zod env schema **fails the build** when it is true and `VERCEL_ENV === "production"` (the exact pattern spec 003 established for `ENABLE_PSEUDO_LOCALES`), and the route answers 404 when the flag is off.
- **Not Storybook**: a second build, a second styling entry point, ~100 MB of devDependencies and a second place for a solo founder to keep components alive, in exchange for controls we do not need. The gallery is ~200 lines, uses the app's own build, and doubles as the cheapest possible visual-regression and axe surface: one screenshot and one axe run cover every component, which is why the visual suite gets a real gate here instead of four blank pages.

**Budgets, headers and CI (`plan/01` §7 §9, `plan/12` §5, spec 001 deferred rows)**

- **The inherited client-JS budget is stated and met.** Baseline: 304 KB script on `/`, 0.88–0.93 performance, against 120 KB gz and 0.95. If spec 003's TASK-043 has not already broken zod out of the client Sentry import chain and trimmed the browser SDK, task 2 of this spec does it, and the recorded decision is: **no browser Sentry SDK on public marketing/shop routes in Phase 0** (server-side and edge Sentry unchanged; the client SDK returns on the checkout routes in spec 013, where a client error costs money). §13 Q8 asks the founder to confirm.
- **CSP** (spec 001's deferred row): a static, per-environment policy delivered as response headers from `next.config.ts`, `Report-Only` in this spec with `/api/csp-report` as the collector, plus `Strict-Transport-Security`, `X-Content-Type-Options`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options`/`frame-ancestors 'none'`, `Permissions-Policy` and `Cross-Origin-Opener-Policy`. `vercel.live` is allowed **on preview only** (the second deferred row, `ci.yml`'s known preview-feedback script) and is absent from the production policy — asserted by a test on both header strings. Shape, and why it is not nonce-based on cached pages, in §5.2.
- **Lighthouse enforced**: `tests/fixtures/seo/lighthouse-urls.json` becomes `["/", "/en", "/en-gb", "/de", "/pl"]` and `continue-on-error: true` is deleted from the `lighthouse` job. Assertions gain `categories:accessibility` and `categories:best-practices` ≥0.95, `total-byte-weight`, `unused-javascript` and an explicit **exclusion of `categories:seo`** with the reason in a comment: the SEO category penalises `noindex`, which is deliberate until spec 007, and nobody may "fix" that score by indexing early.

It prints the table of §11 to the GitHub step summary.

## 4. User stories

- As a **buyer on a phone**, the page is legible and branded in under two seconds, the header does not jump as the font loads, and I can pick a destination before any JavaScript has run.
- As a **buyer in the EEA**, the first thing I can do is refuse analytics as easily as accept them, nothing tracks me before I answer, and I can change my mind from the footer on any page.
- As **Googlebot**, the HTML is complete, the layout adds no client-side content, no link I can follow returns a 404, and the page still says `noindex` because nothing here is a true page yet (ADR-0007).
- As the **founder pitching a Warsaw florist in mid-October**, the site looks like a real company and claims nothing it cannot show: no invented reviews, no invented registry number, no invented florist count, no stock photo pretending to be our bouquet.
- As a **screen-reader user**, there is a skip link that becomes visible when focused, one `<h1>`, named landmarks, a focus ring I can see on every surface, and a consent banner that neither traps nor steals my focus.
- As an **implementer agent on spec 008**, there is exactly one grid, one container, one vertical rhythm, one focus ring and one way to render an image, and `pnpm lint` fails the moment I invent a colour.
- As the **reviewer agent**, "does this component meet contrast?" and "is this cookie declared?" are unit tests, and "did the design system blow the budget?" is a table in the CI summary.
- As a **future RTL launch**, `/ar-XB` has been screenshotted against the real header, footer and home layout since Phase 0, so the first Arabic page is a translation job.

### 5.2 API / server actions / jobs / events (zod schemas named)

Two route handlers, no jobs, no events, no server actions.

- **`POST /api/consent`** — `no-store`, `X-Robots-Tag: noindex`, inside spec 001's `/api/` robots disallow. Body parsed by **`ConsentDecisionSchema`** (`{ cid: uuid, policyVersion: int, analytics: boolean, marketing: boolean, decidedAt: ISO datetime }`); rejects anything else with 400 and logs nothing but the failure count. Hands the parsed decision to a **`ConsentSink`** (`record(decision)`); Phase 0 implementation `logConsentSink`. No IP, no user agent, no `Referer`, no page URL is read or stored (§8).
- **`POST /api/csp-report`** — accepts `application/csp-report` and the Reporting-API JSON shape, parsed by **`CspReportSchema`**, and logs **only** `effective-directive` and the *origin* of `blocked-uri` (never the full URL, never `document-uri`'s query, never `script-sample`, which can contain user content). `no-store`, `noindex`, and it never fails a request: an unparsable body is a counter, not a 500.

The `src/modules/ui` public surface:

```
src/modules/ui/
  index.ts            the only import path for everything below
  tokens/             tokens.md (the documented ramp), contrast.ts (the pair manifest), scale.ts (type/space names as types)
  primitives/         Container, Stack, Row, Grid, VisuallyHidden, SkipLink
  layout/             SiteHeader, SiteFooter, PageShell
  trust/              TrustStrip, TrustMarks (empty state), CompanyIdentity
  home/               Hero, HowItWorks, DestinationPicker
  consent/            ConsentBanner (island), ConsentSettings (island), consentState.ts, ConsentDecisionSchema, ConsentSink
  media/              Media, loader.ts (placeholderLoader now, R2 later), slots.ts (the `sizes` table)
  icons/              five inline SVGs with per-icon mirroring intent
```

Other schemas: **`CountryConfigSchema`**, **`SiteLinkSchema`** (id, page type, `published`, owning spec), **`CompanySchema`** (registry fields optional, refined so `registered: true` requires them all — so "registered" cannot be claimed without the data), **`CookieRegistrySchema`** (unique names; every non-essential entry requires a category and a lifetime).

**CSP shape, and why it is not a nonce on cached pages.** The policy is a constant per environment, emitted as a header, and the only inline script in the app is the ≤1 KB Consent Mode default block:

| Directive | Value | Note |
|---|---|---|
| `default-src` | `'self'` | |
| `script-src` | `'self'` + `'sha256-…'` for the consent bootstrap + (`https://www.googletagmanager.com` when GA4 is configured) + (`https://vercel.live` **preview only**) | A build-time **hash** for our one inline script, not a nonce: it is identical in every response, which is precisely why a hash works on a cached page and a nonce does not |
| `style-src` | `'self' 'unsafe-inline'` | React sets `style` attributes and Next inlines critical CSS; documented as a known relaxation with the reason, revisited if either stops being true |
| `img-src` | `'self' data: blob:` + the R2 host when 006 configures it | |
| `font-src` | `'self'` | Self-hosted font; no Google Fonts origin, ever |
| `connect-src` | `'self'` + Sentry ingest + (GA4 when configured) + (`vercel.live` preview only) | |
| `frame-src` | `'none'` in Phase 0; Stripe/3DS origins added by 013 | |
| `frame-ancestors` / `base-uri` / `object-src` / `form-action` | `'none'` / `'self'` / `'none'` / `'self'` | |
| `upgrade-insecure-requests`, `report-uri`/`report-to` → `/api/csp-report` | | Report-Only in this spec |

The trade-off, stated so the reviewer does not have to infer it: an allowlist plus one script hash is **weaker** than `'strict-dynamic'` with a per-request nonce, because any XSS that can inject a `<script src>` to an allowlisted origin (in practice `googletagmanager.com`, which hosts arbitrary container code) is not blocked. What it buys is that every indexable page stays SSG/ISR at the edge, which is priority #1 and #2 and the entire LCP budget. The mitigation is the split: **cached routes get the allowlist policy; `no-store` routes (checkout, account, admin, vendor — all `noindex` and all dynamic by design) get a per-request nonce from `src/proxy.ts` and `'strict-dynamic'`**, written by the spec that ships the first such route. The three highest-value targets for XSS in this product are the checkout and the two authenticated surfaces, and they are exactly the routes that can carry a nonce. §13 Q5 asks the founder to accept this as ADR-0016.

### 5.4 Rendering & caching (per plan/01 §3)

- `/` chooser: **SSG**, unchanged, still zero application JS.
- `/{locale}` home: **ISR**, `revalidate` 3600, tag `home:{locale}` — the wiring spec 003 already put in place; 004 adds content to it and no new data source, so nothing is invalidated at runtime and `src/lib/cache.ts` stays the noop seam.

## 6. SEO considerations (mandatory)

- **Indexability is unchanged: nothing becomes indexable here.** `src/app/robots.ts` keeps `Disallow: /`, the non-production blanket `X-Robots-Tag: noindex` stays, localised documents keep `noindex,nofollow` and `/` keeps `noindex,follow` until spec 007 lifts them by rule (ADR-0007). `/dev/components` is `noindex` and env-absent in production. A styled site is not a true page.
- **Canonical, hreflang, sitemaps, schema: none emitted** (spec 007). The preconditions are preserved rather than advanced: one URL form per (locale, path), `localePath()` as the only URL builder, `alternatesFor()` untouched and still filtered by `isLocaleIndexable()`.
- **Internal links are the real SEO content of this spec.** `plan/02` §11 wants crawl depth ≤3 and authority flowing from the locale home to corridor pages; `plan/09` Phase 0 AC 1 wants production to index *only* true pages. 004 builds the graph's frame and leaves it empty on purpose: header nav, footer link lists and the destination picker all render from `site-links.ts` / `countries.ts` and render **nothing** for an unpublished target. Consequences that are the point: **zero internal links to a non-200 URL** (AC-14, checked by an e2e crawl of every link in the header, footer and home of all four locales), zero soft-404s, no phantom URL space for a crawler to discover, and — when 007 flips `guide_published` — a picker and a footer that become navigation with no template edit, which is `plan/09`'s "a new country is data" promise applied to the layout.
- **Thin-content risk.** Four locale homes whose `de`/`pl` copy is an echoed English draft is duplicate content, and this spec is the first one that writes enough copy for that to matter. Three guards, all inherited and all still true: nothing is indexable (robots disallow); `isLocaleIndexable()` returns `false` while a locale's unreviewed share exceeds 5%, which is why the newly drafted `nav`/`footer`/`trust`/`consent`/`home` keys **keep** `de` and `pl` out of hreflang and sitemaps until a native reviewer works the queue; and the home skeleton deliberately renders no module it has no data for, so there is no boilerplate block repeated across locales to be thin *with*.
- **CWV budget impact — this spec's largest SEO effect.** It is the first to add a font, a sticky header and two client islands, and the first where the budgets are *enforced*: `continue-on-error` comes off the Lighthouse job, the URL set grows to `/` plus all four locale homes, and LCP <2.0 s / CLS <0.05 / script ≤120 KB gz / performance ≥0.95 become merge gates (`plan/01` §7, `plan/12` §5, Phase 0 AC 2). Specifically: the LCP element is server-rendered text with the font preloaded and fallback metrics matched, so there is no image dependency and no swap shift; the header's height is reserved, not measured; both banners overlay rather than reflow (CLS delta 0); the picker needs no hydration to work; no third-party script loads before consent and none at all while GA4 is unconfigured. `categories:seo` is deliberately **not** asserted, because the SEO audit penalises `noindex` and that penalty is correct until 007 — recorded in `lighthouserc.json` so nobody removes `noindex` to make a number go green.
- **Crawl efficiency.** No redirects exist to chain; unknown locales still 404 (spec 003 AC-8); the gallery and the pseudo-locales are absent from production by env validation.

## 8. Compliance considerations (mandatory)

- **Data flows added → RoPA.** Two. (1) **Consent records**: an unlinkable random `cid`, a timestamp, the category choices and the policy version, written to a structured log line in Phase 0 and to `consent_log` from spec 002. Lawful basis: **legal obligation** (GDPR Art. 7(1) — we must be able to prove consent); retention 5 years after withdrawal per `plan/07` §1.2; no IP, no user agent, no page URL, so the record is not linkable to a person by us. (2) **Google Analytics 4** as a processor, added to the RoPA and the privacy-policy processor list as **declared but inactive** while `NEXT_PUBLIC_GA4_MEASUREMENT_ID` is unset, and active the moment it is set — the founder flipping that env var is a RoPA-affecting act and is documented as such in the runbook. `docs/compliance/ropa.md` is updated in the same PR; the reviewer confirms at PASS.
- **Lawful basis and consent gating (ePrivacy Art. 5(3) as transposed: EE ECA, DE TDDDG, PL Telecom, UK PECR).** No non-essential storage or access happens before consent: no third-party script loads, no analytics cookie is set, and the only pre-consent storage is the essential `fo_locale` (spec 003) and `fo_consent` itself, both first-party, both set only on an explicit user action, both in the register. Consent Mode v2 defaults to denied for `ad_storage`, `ad_user_data`, `ad_personalization` and `analytics_storage` with `url_passthrough` off, so GA4 — when configured — can only send cookieless pings until an accept (`plan/04` §11, `plan/07` §5, Phase 0 AC 7). Withdrawal is one control in the footer on every page. Consent is not inferred from dismissal: pressing `Esc` records nothing and the banner returns.
- **No dark patterns.** Accept / Reject / Settings are equal in size, weight and contrast (asserted by a visual baseline and by a DOM assertion on the computed styles, AC-20); no pre-ticked non-essential category; no "legitimate interest" pre-consent analytics; no cookie wall; the banner never blocks content or focus. Lifetimes are asymmetric in the user's favour only in the direction the guidelines expect: 6 months for reject, 12 for accept.
- **Price display (`plan/07` §4).** No price is rendered in this spec. What it does ship is the *claim* — "price includes delivery and VAT" — in the trust strip, and the rule that makes it keepable: the claim is a message key placed by this spec on pages that show no price, and 008/009 render prices only through `formatMoney` on integer minor units, so the strip cannot end up next to a price that excludes VAT. No drip pricing exists to disclose yet; no "was/now" component ships (Omnibus 30-day rule) precisely so that 005 must build it deliberately.
- **Consumer information (`plan/07` §6).** The footer is the site-wide identity surface, and it tells the truth about a company that does not exist yet: trading name and contact channel now; registry code, address and VAT id only when `company.registered` is true, enforced by the schema refinement so the flag cannot be set without the data. `/de/impressum`, `/de/rechtliches/agb` and `/pl/regulamin` are reserved as unpublished targets on the paths the German and Polish regimes expect, so the Impressum lands on the right URL in 007 rather than being retrofitted.
- **Reviews and trust (`plan/07` §7, Phase 0 AC 6).** Zero reviews, zero testimonials, zero ratings, zero Trustpilot widget or score, zero star icons, zero "1,240 customers" copy, zero demo partner name or photo, zero delivery-photo claim. `TrustMarks` renders an empty state and the visual baseline records that it is empty. AC-15 makes this a grep-able, testable fact rather than a design intention, which is what `plan/09` AC 6 asks for.
- **Accessibility (EAA / WCAG 2.1 AA, `plan/07` §8).** The conformance work of this spec is the design system: a contrast-tested palette (1.4.3, 1.4.11), a visible focus indicator on every surface (2.4.7), keyboard operability of the only interactive components that exist (2.1.1), a visible skip link (2.4.1), reflow and 200% text without loss (1.4.4, 1.4.10), reduced-motion respect (2.3.3), 44 px targets, named landmarks and one `<h1>` (1.3.1, 2.4.6), non-modal non-obscuring banners (1.4.13, 2.2.2), and no colour-only meaning (1.4.1). axe runs on all four locale homes, `/`, the gallery, a 404, the 500 boundary and `/ar-XB` with **no exception list**. A manual VoiceOver pass over the home and the consent flow is a phase-gate item recorded in the runbook, because axe cannot judge the equal-weight requirement or a focus order.
- **Logs and PII.** No PII enters a log, a URL, an analytics call or a cookie. The consent record is an unlinkable id; `/api/csp-report` logs a directive name and a blocked *origin* and explicitly discards `document-uri`, `script-sample` and any query string (a CSP report is a classic accidental PII leak); the consent island transmits no page URL; `fo_consent` contains no identifier beyond its own random id. GA4, when configured, receives the `plan/04` §14 dimensions and no personal field — enforced by spec 023, declared here.
- **Security.** CSP `Report-Only` plus HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'`, `Permissions-Policy` and COOP land here (spec 001's deferred row). `vercel.live` is allowed on preview only and absent from production, asserted on both header strings. `ENABLE_DEV_UI` is refused in production by the env schema, so the gallery cannot be exposed by configuration mistake. No new dependency handles a secret; the font is committed, not fetched.

- **Alerts.** None. The nearest thing is a red required check: a token that fails contrast, a cookie outside the register, a link to a 404 or a blown budget is a failed build rather than a production incident, which is the point of putting all four in CI.

- **Q5 — CSP: accept the allowlist-on-cached-HTML / nonce-on-no-store split, as ADR-0016?** `plan/01` §9 says "CSP with nonces". **A18 — `/`'s LCP has no design-safe margin to win, and why the number is the measurement origin
rather than the page (§9 AC-24; §14 A12, A14; TASK-056).**
Original: §14 A14 fixed the locale documents' LCP by making the `H1` the largest contentful element
instead of an `ssr: false` island, and left `/` unexamined.
Measured (`/review 61` and TASK-056 round 2, `lighthouserc.json`'s mobile profile against the
Brotli origin, warmed) across two passes of three runs each: `/` reports **2 425 / 2 106 / 1 952**
and **2 660 / 2 181 / 1 930 ms** against the 2 000 ms assertion, where the four locale documents
report 1 430–1 649 ms in the first pass and 1 436–1 636 ms in the second. Three things were
established before any change was proposed:

1. **The LCP element on `/` is the chooser's intro `<p>`, and no design-safe change makes it the
   `H1`.** Measured in Chromium at Lighthouse's own 412 × 823 profile: the intro is 380 × 96 px
   (33 943 px² as an LCP candidate, four lines at `text-md`), the `H1` "Choose your language" is a
   **single line**, 380 × 30 px, 11 560 px². A14's fix on the locale homes worked because the two
   blocks there were within ~25 % of each other; here the intro is roughly three times the
   heading. Splitting it at its sentence boundary leaves a three-line block of ~27 000 px², still
   more than twice the `H1`; nothing short of deleting the founder-reviewed copy or halving the
   body step would reverse the order, and both are changes to the design, not to a metric.
2. **It would not matter if it did.** In a real browser `/` emits exactly **one** LCP candidate, at
   **112 ms** — heading and paragraph are painted in the same frame, because `/` is SSG, reaches no
   client module and has no island to wait for (AC-7, AC-27). There is no element-specific render
   delay on `/` to remove.
3. **The number is the render-blocking stylesheet's queue position on an HTTP/1.1 origin.** `/`'s
   LCP tracks when the **later** of its two render-blocking stylesheets finished. Pass 1: CSS at
   613 ms → LCP 2 425; 307 → 2 106; 258 → 1 952. Pass 2: 622 → 2 660; 275 → 1 930; 258 → 2 181 —
   the ordering is not exact at the bottom of the range, but the slowest run of each pass is the
   run whose stylesheet arrived ~600 ms late, and the stylesheet's own spread (258–622 ms) is the
   same order of magnitude as the LCP spread it produces. On the locale documents both stylesheets
   land at 130–185 ms every time and LCP is 1 430–1 649. The cause is
   that `/` is the **fastest** document in the set, not the slowest: it is 4 200 B of SSG and
   arrives at ~20 ms, so its document, three preloaded font faces, two stylesheets and eight
   script chunks are all requested in one burst against `scripts/seo/brotli-origin.ts` — a plain
   HTTP/1.1 proxy, six connections, no multiplexing — and an 804 B stylesheet lands behind a
   17 KB font. The locale documents are 15 KB of SSR and arrive at ~113 ms, which spreads the same
   burst out. Lantern then amplifies the observed queueing under the throttled mobile model.

Decided (TASK-056, taking the option `/review 61` left open): **the assertion is not weakened and
the page is not changed.** 2 000 ms stays an `error`, the URL set stays five, and this amendment is
the record that the remaining margin on `/` is thin — 48 ms in pass 1, 70 ms in pass 2, on the best
of three runs each — and that the lever is the origin, not the document. Two consequences are written down rather than acted on here,
because both are decisions above an implementer:

- **The aggregation is `optimistic`, not median.** `@lhci/cli` defaults `aggregationMethod` to
  `optimistic`, which for a `maxNumericValue` assertion takes the **fastest** of the three runs —
  so `/` passes on 1 952 / 1 930 ms while its median is 2 106 / 2 181 ms. `lighthouserc.json` does
  not set the key,
  and TASK-056 deliberately does not set it either: `"median"` is the honest setting and it would
  make this required check red on `/` today. Flipping it is a gate-strength decision for the
  founder/orchestrator, taken together with the origin question below.
- **The origin is HTTP/1.1.** Serving the measured build over HTTP/2 (multiplexed, no
  six-connection cap) is what a CDN does in production and is what removes this queue. It is a
  change to A12's measurement basis — the decision that made the budget measurable at all — so it
  belongs to whoever revisits A12, not to a round-2 fix.
