## 1. Problem

`plan/02` §5 calls the corridor page "the SEO backbone" and `plan/09` makes it the first thing production is allowed to index (Phase 0 AC 1: "Production indexes only: home, all-destinations, PL corridor (guide state until live), 6 guide corridors, …"). Today none of it exists. Specs 003 and 004 built the frame and deliberately left it empty: `robots.txt` still says `Disallow: /`, every localised document still says `noindex,nofollow`, no page emits a canonical, an hreflang tag, a sitemap entry or a line of JSON-LD, and the seven destinations in `src/config/countries.ts` all carry `corridorPagePublished: false` and `guidePublished: false` so the home finder and the destinations grid link nowhere (spec 004 AC-11, AC-14). The founder's 2026-09-14 decision — the browsable website is the top priority — puts this spec on the critical path: it is the first page type with a reason to be indexed, and the first that turns the finder into navigation.

The failure modes are all known and all documented in `plan/02` §1 and §15 from the competitor study: 14,443 FloraQueen collections of which 12,610 are programmatic; 33,392 city entries with 4,542 duplicates on floristsonline.net; "Empfänger in Frankreich" leaking onto fleurop.de's Poland page. Every one of them is a template that was allowed to render for a place we had nothing to say about. So this spec is only secondarily about a page: it is about the four gates that make the page trustworthy — the **existence rule** (`guide_published = true OR status = live`, `plan/02` §5.1; a country that fails it has no URL at all, not a thin one), the **minimum unique data** rule (`plan/02` §5.2, enforced by a CI content gate rather than by good intentions), the **translation gate** (`plan/02` §12: corridor guides never ship machine-translated, even noindexed), and the **one predicate** rule (the page, the sitemap, the hreflang cluster, the internal links and the robots meta all answer from the same function, so they cannot disagree — `plan/02` §8, §10).

It is also the spec where "indexable" stops being hypothetical. Spec 001's three SEO validators (`seo:validate` → hreflang / sitemap / schema) have run against fixtures with nothing real behind them since 15 Sep. This spec gives them their first real URL set, and it introduces the indexability rule engine that specs 008–011 register their page types against instead of each inventing a `noindex` branch.

## 2. Scope

Each bullet is testable; §9 names the AC. Nothing here requires a database (spec 002 is still unprovisioned), a custom domain, a partner or an image of a country.

**The content model (`plan/02` §5.2, `plan/03` §5, spec 002 §5.1's `country_locale_content`)**

- **`content/corridors/{locale}/{iso2}-{state}.md`** — one human-authored markdown file per (country, locale, state), `state ∈ guide | live`, with YAML frontmatter carrying the structured half: `seoTitle` (≤60 chars), `seoDescription`, `h1`, `intro` (120–200 words), `faq` (8–12 `{q, a}` items), `localFlowers`, `taboos`, `relatedIso2` (exactly 3), `source: human`, `reviewed`, `reviewedBy`, `reviewedAt`, `version`, `updatedAt`. The markdown body is the guide (≥600 words country-specific, `plan/02` §5.1). The file layout is chosen because this is prose a human (the founder, then the `plan/13` B12 native reviewers) edits and diffs, and because it maps field-for-field onto the table spec 002 already defines — `content/` is where `plan/03` §5 already puts long-form copy, and `src/config/` is where zod-parsed registries live, so the frontmatter is parsed by the same zod discipline while the prose stays readable.
- **`CountryContentProvider`** in `src/modules/geo/content/` — `staticCountryContentProvider` reads the committed files at build time (no runtime fetch, no `fs` in the bundle: the files are imported through a generated typed index); `dbCountryContentProvider` reading `country_locale_content` arrives with spec 002/012 as a second implementation behind the same interface, with **no call-site change**. This is spec 003's registry seam and spec 005's provider seam applied again (spec 006 §2.1's provisioning-seam table is the precedent).
- **`toCountryLocaleContentRow()`** projects a parsed file onto spec 002 §5.1's `country_locale_content` columns exactly, pinned by a unit test on the column list, so the CMS (spec 012) inherits the content rather than re-keying it.
- **`pnpm corridor:check`** (new CI job `corridor-check`, `needs: typecheck`, the job-placement rule of spec 001 §14 A9) is the gate that makes `plan/02` §5.2 a fact. One line per problem naming file, field and rule. It fails on: a file that does not parse; `source: machine` anywhere (corridor copy is never machine-drafted — `plan/02` §12); guide body <600 words; intro outside 120–200 words; **<70% token-distinct** from every other corridor page in the same locale (the `plan/02` §5.2 uniqueness test, computed on a normalised token multiset with stop-words retained); fewer than 8 or more than 12 FAQ items; <50% of FAQ questions country-specific (a question that does not name the country, a city in it, its currency, its language, one of its occasions or one of its customs counts as generic); `seoTitle` >60 characters or absent; `seoDescription` absent or >155 characters; the country's own slug appearing inside body prose (the `plan/02` §5.3 grep); any **other** country's name or slug in the body (the fleurop.de failure); any of the nine banned words of `docs/design/README.md` §Voice; any delivery-timing, cutoff, "same-day", florist-count, rating, review or delivery-photo claim in a `guide`-state file (§8); any digit-bearing claim of scale ("200+ florists"); a price literal anywhere in copy (prices are data, `formatMoney` only); a `live`-state file for a country whose `operations` block is incomplete.

**The page, in its two states (data, not code — `plan/02` §5.1, `plan/09` "a new country is data")**

- **Guide state** (Phase 0, all seven destinations): H1 + authored intro; "how we work here" in our own first-person voice (spec 004 §14 A5); the **local occasion calendar** for the next 12 months computed from `occasion_country` data; locally popular flowers and taboos; the **region-specific FAQ** (8–12 Q&A, visible server-rendered text, no accordion, no JS); an honest "where we deliver" block that states what is true today and claims no cutoff, no florist and no date; breadcrumb; related destinations; links out to whatever is published. No product grid, no price, no partner, no review, no delivery photo.
- **Live state** (Phase 1, PL first): the same template with the delivery-facts block populated (same-day cutoff in the recipient's local time with the zone named, next-day window, Sunday/holiday rules), the from-price, and the **shop entry** — the handoff to spec 008's country shop root and categories. This spec ships the state, its view model and its empty/disabled branches; the product grid itself is 008's (§3).
- **`corridorState(iso2)`** is the one function that decides: `live` only when `country.status === 'live'` **and** `hasActivePartners(iso2)` **and** a `live`-state content file exists **and** the country's `operations` block is complete; otherwise `guide`. `hasActivePartners` is a provider (`staticNoPartnersProvider` returns `false` for every country in Phase 0, because we have no florists; spec 002/011 supply the real one). This is what stops `countries.ts`'s `status: "live"` on PL — a design label, not an operational fact — from rendering a cutoff we cannot honour (§13 Q3).

**Existence, URLs and routing (`plan/02` §4.1, §5.1)**

- `/{locale}/{destinations}/{countrySlug}` with `destinations` from `locales.data.ts` (`send-flowers-to` / `blumen-verschicken` / `wyslij-kwiaty`) and `countrySlug` from `countries.ts` — both already authored, both consumed only through `localePath(locale, "destinations", slug)`, which stays the single URL builder (spec 003 §6).
- `/{locale}/{destinations}` is the **all-destinations hub** (`plan/05` #3, Phase 0, required by `plan/02` §11 for crawl depth ≤3 and named in `plan/09` Phase 0 AC 1): every existing corridor grouped by region, each with its status, and every destination that has no page rendered as plain text with its state line — the same published/unpublished rule the finder already obeys.
- **A corridor URL exists iff** `(status === 'live' || guidePublished)` **and** a parsed content file exists for that (country, locale, state). `generateStaticParams` emits exactly that set and `dynamicParams = false`, so every other slug, every other path segment and every casing variant is a hard 404 — the existence rule is structural, not a runtime branch, and `plan/02` §6's "pages that fail the rule are not created (404), not `noindex`" holds by construction.
- Depublishing is the same flip in reverse. `410` for a corridor that was once published is Phase 1 (§3): in Phase 0 no corridor URL has ever been announced, so a removed page is a 404 and no `disabled` transition exists yet.

**Indexability, canonical, hreflang, robots (`plan/02` §7, §8, §12; ADR-0007)**

- **One rule engine.** `src/modules/seo/indexability.ts` takes a `PageDescriptor` (`pageType`, `locale`, plus the page's own gates) and returns the robots directive, the canonical URL, the alternates and the sitemap membership from a **single** decision. A corridor page is indexable when it exists **and** its content record is `reviewed: true` **and** `isLocaleIndexable(locale)` (spec 003's ≤5% unreviewed-share gate) **and** the deployment is an indexing environment. Otherwise `noindex,follow` and out of every sitemap. Specs 008–011 register their page types here instead of writing their own branch.
- **The environment gate.** There is no custom domain yet. `isIndexingEnvironment()` is true only for a production deployment whose `NEXT_PUBLIC_SITE_URL` host equals the canonical host; everywhere else spec 001's blanket `X-Robots-Tag: noindex` and `Disallow: /` stand unchanged. So this spec is fully implementable, testable and reviewable today, and the actual lifting of `noindex` is a configuration flip at the end of Phase 0 (§12, §13 Q5).
- **`robots.txt` gains its real policy** in the indexing environment: `Disallow` for `/api/`, `/admin/`, `/vendor/`, `/account/`, `/checkout/`, `/search`, the facet parameter shapes and the `(dev)` group; `Allow` everything else; exactly one `Sitemap:` line pointing at `/sitemap.xml` (`plan/02` §10). Facets are **not** disallowed as URLs so their `noindex` can be seen (`plan/02` §7) — only the `?`-parameter shapes named there.
- **Canonical**: self-canonical, absolute, lowercase, no trailing slash, no parameters, built by `absoluteUrl()`; never cross-locale, which the alternates builder is structurally incapable of expressing (spec 003 §6).
- **hreflang**: emitted in `<head>` **and** in the sitemap from the same `alternatesFor()` call, over indexable locales only, with `x-default → /en`, the regional aliases of `plan/02` §3, and the `en-150` non-emission ruling of spec 003 §14 A5 inherited unchanged. A locale without an authored, reviewed content file has no page and therefore no alternate — which is the honest answer and the reason the `de`/`pl` clusters start empty (§7, §13 Q1).

**Schema (`plan/02` §9)**

- Typed builders in `src/modules/seo/schema/`: `BreadcrumbList` on the corridor and the hub (mirroring the visible breadcrumb exactly); `FAQPage` built **from the same view model the FAQ block renders**, so markup and visible text cannot diverge, and emitted only where 8–12 visible Q&A exist; `Organization` on the locale home carrying only the fields we actually have (`name`, `url`, `logo`) and gaining `address`/`vatID`/`sameAs` only when `company.registered` is true; `WebSite` without `SearchAction` until spec 008 ships search. **Never** `LocalBusiness`, never a per-city entity, never `Product`/`Offer`/`aggregateRating` on a corridor page, and never an `Offer` for a country that is not live (`plan/02` §9, §15). CI validates the JSON-LD of both corridor states and the hub through spec 001's `validate-schema`.

**Sitemaps (`plan/02` §10)**

- `/sitemap.xml` (index) → `/sitemaps/{loc}/index.xml` → `/sitemaps/{loc}/static.xml` (home, hub) and `/sitemaps/{loc}/corridors.xml`. The other children of `plan/02` §10 are absent from the index until their specs ship (an absent child is correct; an empty one is noise). Route handlers, `Cache-Control: max-age=3600`, ≤10,000 URLs and ≤10 MB per child, `xhtml:link` alternates on every URL, and `<lastmod>` from the real maximum `updatedAt` across the content file, the country registry entry and the message catalogue — never "now". Nothing `noindex` can appear, because membership and the robots directive come from the same predicate.

**Internal links (`plan/02` §11) — the link contract 008 inherits**

- Locale home → hub + published corridors (the finder and the destinations grid become navigation when `corridorPagePublished` flips; **no markup change**, spec 004 AC-11). Footer → top destinations for the locale + the hub. Hub → every existing corridor, grouped by region, in `collator(locale)` order.
- Corridor → breadcrumb (home → hub → country); 3 related corridors from `relatedIso2`, asserted reciprocal and rendered only where the target exists; and, **gated on `isPublished(linkId)` and the target's own existence predicate**, the country shop root, up to 6 country categories, the indexable country occasions, the occasion hubs and country-tagged blog posts. Those five link ids are the contract spec 008 (and the later blog work) satisfies: publishing them is a data flip in `site-links.ts`, and until then the section is **not rendered at all** — never a disabled link, never a link to a non-200 (spec 004 AC-14, extended here to the new routes).

**Occasion dates (`plan/03` §9, `plan/13` B15)**

- `src/modules/geo/occasions/` implements `occasionDate(rule, year)` for the six rule types of `plan/03` §9 (`fixed`, `nth_weekday`, `last_weekday`, `easter_offset`, `lent_sunday`, `none`) plus `nextOccasions(iso2, from, n)` over spec 006's committed `occasion-country` data, with the 2026–2030 fixture table of `plan/03` §9 and `plan/13` D6 and **100% branch coverage** (`plan/12` §4 names `modules/geo/occasions` as one of the four modules where a bug costs money or rankings). It lands here because the corridor calendar is the first consumer; spec 009 consumes the same function for the date picker and owns the seventh rule type (B15). An occasion whose rule is `none` is listed without a date only in the "also observed here" line, never with a guessed date.

**Rendering, budget and gates**

- ISR, `revalidate` 86400, tags `corridor:{iso2}`, `corridor:{iso2}:{locale}` and `sitemap` through `src/lib/cache.ts` (`plan/01` §3). No `Vary`, no cookie read, no `Set-Cookie`, no client data fetch, and **zero new client islands** — the FAQ is text, the calendar is a table, the breadcrumb is a list.
- Lighthouse URL set gains one corridor URL per indexable locale plus the hub; axe gains both corridor states and the hub; visual baselines (both platforms) gain corridor desktop/mobile in both states and the hub; `seo:validate` gains real fixtures generated from the built URL set.
- Docs: `docs/runbooks/corridor-content.md` (how to author, review, run the gate, publish a country, read a `corridor:check` failure), `docs/architecture.md` §2/§3, `docs/codebase-map.md` regenerated, `README` scripts, `messages/*.json` namespaces.

## 3. Non-goals

- **City corridor pages** (`plan/05` #5, `plan/02` §5.1's city rules) → Phase 1/4, and only where a partner actually covers the city. No city URL pattern is created here, so none can leak into a sitemap.
- **The live-state shop UI beyond the seam**: the product grid, category tiles, the from-price block's internals, the currency menu and the price repaint → spec 008; the PDP → spec 009. This spec renders the *slots* and the honest empty branch.
- **Reviews, ratings, partner profiles, florist counts and delivery-photo galleries** → real data only, spec 022/027 (`plan/07` §7, `plan/09` Phase 0 AC 6). The blocks `plan/02` §5.2 lists for them are not rendered while the data does not exist.
- **Waiting-list / notify-me capture on a guide page** → it is a new personal-data flow with its own lawful basis and RoPA row; deferred (§13 Q4).
- **The other Phase 0 information pages** — how it works, guarantee & delivery, about/contact/help, blog, the legal template and the cookie-policy page — even though `docs/design/README.md`'s wireframe table currently attributes their artboards to "007". They are lawyer-gated (`plan/13` B4) and unrelated to the corridor template; they need their own spec (§13 Q6). Their `site-links.ts` targets stay unpublished, so the footer does not grow and no link points at a 404.
- **Checkout, basket, tracking, account** → 010/013/018/019.
- **The database.** No migration runs here; spec 002 owns `country_locale_content` and this spec requests one amendment to it (§5.1).
- **Editing `CLAUDE.md`, `plan/*` or an accepted ADR.** Two bounded, stated deviations are carried rather than resolved (§12): the config-file publish flags (spec 003 §12 / spec 004 §12 precedent, until spec 012's admin owns them) and `docs/design/README.md`'s 007 artboard rows (§13 Q6).

## 4. User stories

- As a **buyer in London searching "send flowers to poland"**, the first page I land on tells me whether you can really deliver there, what happens on the day, what flowers mean there, and what I should not send — before it tries to sell me anything.
- As a **buyer in Berlin on `/de/`**, picking Poland keeps me in German and takes me to a page written for me, not a machine translation of an English one — and if that German page has not been written yet, the site says so instead of pretending.
- As **Googlebot**, every corridor URL is complete server-rendered HTML with one self-canonical, a reciprocal hreflang cluster that matches the sitemap byte for byte, valid `BreadcrumbList` and `FAQPage` matching the visible text, and no link to a URL that is not 200.
- As the **founder pitching a Warsaw florist**, the Poland page reads like a company that already understands Poland, and it claims no cutoff, no florist and no review that we do not have.
- As the **founder publishing Romania**, going live is: write the file, run `pnpm corridor:check`, flip two booleans. No template edit, no deploy-time surprise, no sitemap to remember.
- As the **seo-auditor agent**, "does the indexable corridor set exceed the countries with `guide_published = true OR status = live`?" is a query over one function, and a build that breaks it fails.
- As an **implementer on spec 008**, the corridor page already declares which link ids I must publish and what the shop-entry slot expects, so publishing the shop is a data flip plus a component, not a redesign of the corridor.

## 5. Design

### 5.1 Data model changes (tables, columns, migrations + rollback)

**No migration runs in this spec** — spec 002 is unprovisioned and the corridor's persistence target (`country_locale_content`) is already specified there. Phase 0 reads committed content files through the provider seam; `pnpm check:no-db` covers every file this spec adds.

Three contracts keep the file half and the table half from drifting:

| Phase 0 (this spec) | Later owner | Contract |
|---|---|---|
| `content/corridors/{locale}/{iso2}-{state}.md` + `CountryLocaleContentSchema` | spec 002's `country_locale_content`; spec 012's admin editor | `toCountryLocaleContentRow()` projects exactly the table's column list; a unit test pins the list so the two cannot be edited apart |
| `countries.ts` gains an **optional `operations`** object (`ianaZone`, `sameDayCutoffLocal`, `deliveryDays`, `sundayDelivery`), absent for every country until the founder has real values | spec 002's `country` operational columns | `COUNTRY_ROW_COLUMNS` and `toCountryRow()` grow together, pinned by the existing test; a schema refinement makes a complete `operations` block a precondition of the live state, so a cutoff cannot be rendered unless it was authored |
| `relatedIso2` (3 per country, authored in frontmatter) | a `country_related` table or a `country_locale_content` column when 012 needs to edit it | `corridor:check` asserts reciprocity and that every target exists |

**Requested amendment to spec 002 §5.1** (the mechanism spec 003 §14 A13 used): `country_locale_content` gains `seo_title text` and `seo_description text`, because `plan/02` §5.3 requires an authored per-country title (≤60 chars) and meta description and the table as specified has nowhere to put them. Rollback of the amendment is a column drop; it changes no shipped code because nothing reads the table yet. If the founder prefers, the alternative is a `country_translation` extension — recorded in §13 Q10.

**Rollback of this spec** is `git revert` of its task commits plus setting the two booleans in `countries.ts` back to `false`: no state, no migration, no external resource. Because no corridor URL is announced before the indexing flip (§12), a revert cannot orphan an indexed URL.

### 5.2 API / server actions / jobs / events (zod schemas named)

No server action, no route handler that accepts input, no job, no event, no cookie. The additions are two modules, two page routes and the read-only sitemap/robots handlers.

```
content/corridors/{locale}/{iso2}-{guide|live}.md      authored copy (markdown + frontmatter)

src/modules/geo/
  index.ts                the only import path
  corridor.ts             corridorState, corridorPageExists, corridorPageIndexable, listCorridorPages,
                          corridorView (the one view model the page, the schema builders and the
                          sitemap all read)
  content/                CountryContentProvider, staticCountryContentProvider, schemas.ts,
                          projections.ts (toCountryLocaleContentRow)
  partners.ts             ActivePartnersProvider, staticNoPartnersProvider
  occasions/              occasionDate, nextOccasions, rule schemas, 2026–2030 fixtures

src/modules/seo/
  index.ts                the only import path
  indexability.ts         PageDescriptor -> { robots, canonical, alternates, inSitemap }
  canonical.ts            canonicalUrl
  hreflang.ts             thin wrapper over i18n/alternatesFor (never a second generator)
  metadata.ts             buildMetadata (Next Metadata: title, description, canonical, alternates,
                          robots) — the only place a page composes SEO metadata
  robots.ts               the policy app/robots.ts renders
  schema/                 breadcrumbList.ts, faqPage.ts, organization.ts, webSite.ts, JsonLd.tsx
  sitemap/                index.ts, statics.ts, corridors.ts, xml.ts

src/app/[locale]/(marketing)/[destinations]/page.tsx              all-destinations hub
src/app/[locale]/(marketing)/[destinations]/[country]/page.tsx    corridor page
src/app/sitemap.xml/route.ts, src/app/sitemaps/[locale]/[child]/route.ts
scripts/corridor-check.ts  (`pnpm corridor:check`)
```

Zod schemas, parsed at module load (content, registry) or at the route boundary:

- **`CountryLocaleContentSchema`** — the frontmatter above, refined: `state ∈ {guide, live}`; `source` must be `"human"`; `faq` length 8–12 with non-empty `q`/`a`; `relatedIso2` exactly 3, distinct, none equal to the file's own country; `reviewed: true` requires `reviewedBy` and `reviewedAt` (the spec 004 `CompanySchema` pattern: a claim cannot be set without its evidence).
- **`FaqItemSchema`**, **`CorridorViewSchema`** (the rendered view model: state, h1, intro, blocks present/absent, facts, occasions, faq, related, links), **`CountryOperationsSchema`**, **`PageDescriptorSchema`**, **`SitemapEntrySchema`** (`{ loc, lastmod, alternates[] }`).
- Route params are parsed, not trusted: an unknown locale, a `destinations` segment that is not this locale's, or an unknown country slug produces `notFound()` — never a redirect (ADR-0006), never a lowercase-fixing rewrite.

Behavioural contracts worth pinning:

- `corridorView()` is the **single** source for the page, the JSON-LD builders and the sitemap row. Structured data is therefore incapable of describing something the page does not render (`plan/02` §15's third risk).
- `indexability()` is pure and synchronous, so `generateMetadata`, the sitemap builder and the e2e crawl get the same answer.
- `hreflang.ts` calls `alternatesFor()` and adds nothing; a second hreflang generator is a review failure (`plan/02` §8).
- A block whose data is missing renders **nothing** — no heading, no placeholder, no "coming soon" box (the `TrustMarks` empty-state rule of spec 004 §5.3).

### 5.3 UI (pages, components, states: loading / empty / error / demo / disabled)

| Surface | States | Notes |
|---|---|---|
| Corridor page | **guide** · **live** · per-block empty (no photo, no price, no cities, no blog posts, no shop links) | One template. State comes from `corridorState()`; the artboards draw both (§12) |
| Delivery-facts block | facts-known (live) · facts-unknown (guide) | Guide renders the honest "we are choosing florists here" sentence and **no** cutoff, window or date. Live renders the cutoff in the **recipient's** zone with the zone named (`plan/03` §7, §10) |
| Occasion calendar | dated occasions (next 12 months) · undated-observed line · empty (no rows for the country) | Dates via `formatDate`; no hard-coded date anywhere (`plan/09` Phase 3 AC's rule, applied early) |
| FAQ block | 8–12 visible Q&A | Server-rendered `<h3>`+`<p>`, no accordion, no JS, never hidden (`plan/02` §9) |
| Shop entry | published (live + 008 shipped) · unpublished (not rendered) | The link contract of §2 |
| Related destinations | 3 existing corridors · fewer, if a target does not exist in this locale | Never a link to a non-existent page |
| From-price | live only · absent in guide | §13 Q2 |
| All-destinations hub | grouped by region · destination-with-page (link) · destination-without-page (text + state line) · empty | Same rule as the finder, so the two cannot disagree |
| Loading / error | none / the spec 003 localised boundaries | An ISR page has no client loading state; a content parse failure fails the **build**, not a request |

Accessibility: one `<h1>`; `<nav aria-label>` for the breadcrumb with `aria-current="page"` on the leaf; the facts block as a description list; the calendar as a `<table>` with a caption and header scope; FAQ questions as real headings in document order; every new colour pair already in the contrast manifest (spec 004 AC-3); no new focus trap and no new motion.

### 5.4 Rendering & caching (SSG/ISR/SSR, tags invalidated, per plan/01 §3)

- Corridor page and hub: **ISR**, `revalidate` 86400, keyed locale × country, `generateStaticParams` prebuilding the published set (`plan/01` §3's "prebuilds only the live country corridors" generalised to "every corridor that exists", which in Phase 0 is at most 28 URLs), `dynamicParams = false`.
- Tags: `corridor:{iso2}`, `corridor:{iso2}:{locale}`, `sitemap`. `src/lib/cache.ts` stays the invalidation seam; the first real callers are spec 012's admin (a content or status edit) and the hourly sitemap job of `plan/01` §8 — both recorded in the runbook so they inherit the tag list rather than guess it.
- Sitemap and robots handlers: route handlers, `Cache-Control: public, max-age=3600`, no cookie, no `Vary`.
- **No response varies by request header and no cached response sets a cookie** (`plan/02` §14, spec 001 AC-15, spec 003 AC-12, spec 004 §5.4) — asserted by a byte-identical body hash with and without `fo_locale`/`fo_currency`/`fo_consent`.
- Client JS: **none added**. The corridor page ships the same island set as the locale home, which is what keeps it inside the ≤131 072 B Brotli script budget of spec 004 §14 A1.

## 6. SEO considerations (mandatory)

This spec *is* an SEO deliverable, so this section is the contract rather than a note.

- **Indexability.** A corridor page is indexable iff it exists (`status === 'live' || guidePublished`, **and** an authored content file for that locale and state) **and** `content.reviewed === true` **and** `isLocaleIndexable(locale)` **and** `isIndexingEnvironment()`. Everything else is `noindex,follow` and absent from every sitemap. The hub is indexable when at least one corridor in that locale is. The locale home lifts to `index,follow` under the same engine (it is on `plan/09` Phase 0 AC 1's list and it is a true page); `/` stays `noindex,follow` (`plan/02` §7); `/dev/components`, the pseudo-locales and every non-production deployment stay `noindex` (spec 004 AC-28, spec 003 AC-29). ADR-0007 is satisfied exactly: what becomes indexable is corridor guides and the hubs that reach them, and nothing that sells anything.
- **Canonical.** Self-canonical, absolute, lowercase, no trailing slash, no parameters, from `absoluteUrl()`. No cross-locale canonical is expressible. One URL form per (locale, country) is reachable because every other form 404s.
- **hreflang set.** In `<head>` and in `corridors.xml`, from one `alternatesFor()` call, reciprocal and complete, with `x-default → /en`, the `plan/02` §3 regional aliases, and `en-150` present as data but never emitted (spec 003 §14 A5). A locale without an authored reviewed page contributes no alternate. Sampled reciprocity is asserted in CI by spec 001's `validate-hreflang` over the real built set (`plan/02` §8's 200-URL sample becomes "every URL" while the set is small).
- **URL pattern and localised slugs.** `plan/02` §4.1 verbatim: `/en-gb/send-flowers-to/poland`, `/de/blumen-verschicken/polen`, `/pl/wyslij-kwiaty/polska`. Segments from `locales.data.ts`, slugs from `countries.ts`, composed only by `localePath()`. `i18n:check`'s ASCII-lowercase-hyphen and per-locale uniqueness assertions already cover both. The German `rumaenien` and Polish `holandia` forms are revisited **with** the corridor copy, as `countries.ts` says they would be — before any of these URLs is published, which is now (§13 Q8 records the review).
- **Schema types.** `BreadcrumbList` (corridor, hub), `FAQPage` (corridor, visible Q&A only), `Organization` + `WebSite` (locale home, fields we have only, no `SearchAction` until search exists). Forbidden and asserted absent: `LocalBusiness`, `FloristShop`, per-city entities, `Product`, `Offer`, `aggregateRating`, `review` (`plan/02` §9, §15). Schema price = visible price is trivially satisfied: there is no price and therefore no `Offer` — and the same rule is what forbids an `Offer` when 008 adds the grid to a non-live country.
- **Sitemap membership.** `static.xml` (locale home + hub) and `corridors.xml` (every indexable corridor), per locale, under a per-locale index under `/sitemap.xml`. `<lastmod>` = real max `updatedAt`. Nothing `noindex` can appear because both answers come from `indexability()`. `robots.txt` names exactly one sitemap.
- **Internal links in/out.** In: locale home (finder + destinations grid + footer), hub, related corridors, and later every blog post tagged with the country (`plan/02` §11/§12). Out: hub, 3 related corridors, and the published subset of shop root / categories / occasions / occasion hubs / blog. Crawl depth from any locale home to any corridor is 2. **Zero links to a non-200 URL** is preserved and extended to the new routes (spec 004 AC-14).
- **Thin-content and duplication risk — the real ones.**
  (a) *Programmatic thinness*: mitigated by the existence rule (no page without a guide), the 600-word floor, the 70% token-distinctness test, the 8–12 country-specific FAQ floor and the slug/other-country greps of `plan/02` §5.3, all in `corridor:check` and therefore in CI.
  (b) *`/en/` vs `/en-gb/` near-duplication*: two English pages for the same country. They are hreflang alternates (`en` + `x-default` vs `en-GB`) and they genuinely differ in currency, VAT/consumer-law wording and the UK-specific FAQ answers, which is exactly the test `plan/02` §3 sets for deserving a prefix. `en-gb` content files may inherit the `en` guide body via `extends: en` but must override title, description, the price/legal blocks and at least two FAQ answers; `corridor:check` enforces the overrides, and GSC's "Duplicate, Google chose different canonical" is the monitored signal (`plan/02` §4.2's 10% rule applied to this pair).
  (c) *Machine-translated corridor copy*: structurally impossible — `source: machine` fails the gate, so a German corridor page cannot exist until a human writes it (`plan/02` §12).
- **CWV budget impact.** Zero new client JS, zero third-party scripts, no image dependency (no country photography exists; the hero slot renders spec 004's placeholder), so the LCP element is server-rendered text with the font already preloaded. Budgets are spec 004's, unchanged and still enforced: performance/accessibility/best-practices ≥0.95, LCP <2.0 s, CLS <0.05, script ≤131 072 B Brotli. The Lighthouse URL set grows by the hub and one corridor per indexable locale; `categories:seo` becomes **assertable** for the first time on the corridor URLs (the `noindex` reason for excluding it disappears for indexable pages) and is asserted ≥0.95 there while remaining unasserted on the still-`noindex` set.
- **Crawl efficiency.** No redirect exists to chain; unknown slugs and wrong segments 404 immediately; no facet, no calendar and no parameter URL is generated; the sitemap is the only place a crawler learns a URL it cannot reach in two clicks.

## 7. i18n considerations (mandatory)

- **New message keys / namespaces.** `corridor.*` (section headings, the honest "we are choosing florists here" line, the facts labels, the calendar caption, the FAQ heading, the related-destinations heading, the shop-entry CTA), `destinationsHub.*` (h1, intro, region headings, the unpublished state line), `breadcrumb.*`, plus `a11y.*` additions (breadcrumb nav label, calendar caption). All ICU, namespaced, typed; zero literals; `en-gb` overrides only where British wording differs; `de`/`pl` re-drafted by `pnpm i18n:draft` and therefore unreviewed, which keeps `isLocaleIndexable('de'|'pl')` false — the correct answer while the chrome around a page is English (§6).
- **Chrome strings vs corridor content.** The two are different mechanisms and the distinction is load-bearing: the chrome is `messages/*.json` (machine draft allowed, gated by the 5% share), the *content* is `content/corridors/` (machine draft **forbidden**, `plan/02` §12). A corridor page therefore needs both a human-written content file **and** a reviewed locale before it is indexable, and Phase 0 ships `en` (founder-authored) and `en-gb` (founder-authored overrides) complete, with `de` and `pl` as an authoring queue for the `plan/13` B12 native reviewers — the PL Polish guide being the first commission, exactly as `plan/09`'s 29 Sep–5 Oct non-code column says.
- **Locale formatting.** Dates through `formatDate` with weekday and month name (`plan/03` §7), times through `formatTimeInZone` with an explicit IANA zone and the zone named in the copy ("14:00 Warsaw time") — there is no "local time" overload and the corridor page is exactly the surface `plan/03` §10 wrote that rule for. Country and city names come from message keys / `countries.ts`, never concatenated. Lists via `Intl.ListFormat`; destination ordering via `collator(locale)` so Polish `ł` sorts correctly; any future florist count via ICU plurals (`1 kwiaciarnia / 2 kwiaciarnie / 5 kwiaciarni`) — declared now, rendered never, because there are no florists.
- **RTL impact.** No physical CSS, no direction-carrying icon added beyond the existing chevron; the breadcrumb separator is a token, not a character that must flip; `/ar-XB` visual baselines gain the corridor page so the first RTL launch is a translation job.
- **Address/phone formats.** Not rendered here (no form). The corridor's delivery-facts block references the destination's address expectations in prose only; `config/address-formats.ts` stays spec 003's and 010's.
- **Translation review plan and `noindex` gating.** `reviewed` on the content file is the per-page gate, `isLocaleIndexable()` the per-locale gate, and both are inputs to the single `indexability()` decision. A page whose copy is authored but not yet native-reviewed exists, renders, and is `noindex,follow` + absent from sitemaps until the reviewer signs it — which is `plan/02` §12 and `plan/03` §6.4 implemented as data rather than as a promise. Glossary entries for the corridor vocabulary (the guarantee name, "our florists", the occasion names) go into `content/i18n/glossary.{locale}.md` in the same PR, because the native reviewers translate against them.

## 8. Compliance considerations (mandatory)

- **Data flows added → RoPA.** **None.** This spec renders public marketing content, accepts no input, sets no cookie, reads no cookie, adds no processor and stores nothing about a visitor. `docs/compliance/ropa.md` gains an explicit "no new processing" note for 007 (the pattern spec 006 §8 used) so the absence is recorded rather than assumed. Consequence deliberately accepted: **no waiting-list capture** on a guide page in Phase 0 (§3, §13 Q4) — the moment an email field appears, a lawful basis, a consent record, a retention rule and a RoPA row appear with it.
- **Lawful basis / consent gating.** No non-essential storage or access; the consent banner and Consent Mode v2 defaults of spec 004 are inherited unchanged; GA4 (if configured) still sends cookieless pings under default-denied. Nothing on the page requires consent to render, which is why it can be fully edge-cached.
- **Price display (`plan/07` §4, `CLAUDE.md`).** Guide state shows **no price at all** (§13 Q2): a price for a destination we cannot deliver to would be an unavoidable-charge disclosure for a purchase that cannot be made. Live state shows one all-in from-price computed by spec 005's `fromPrice`/`priceProjection` on integer minor units through `formatMoney`, VAT and delivery included, equal to the price the shop charges and equal to any schema price (there is none until 008/009 emit `Offer`). No "was/now", no strike-through, no countdown — an urgency claim is permitted only from real cutoff data (`plan/07` §4), and guide state has none.
- **Consumer information (`plan/07` §6, CRD Art. 6).** The corridor page is pre-contractual marketing, not an offer: it carries no order button and forms no contract. It must nevertheless not mislead, which is what §2's `corridor:check` honesty rules and the `corridorState` gate enforce: no delivery date, window or cutoff without operational data; no florist, count, city coverage or "same-day" claim without a partner; the geography claim capped at live coverage ("across Europe", never "anywhere in the world" — spec 004 §14 A5). The footer's identity block and the reserved legal targets are unchanged; the legal pages themselves stay lawyer-gated (`plan/13` B4) and unpublished (§3).
- **Reviews and trust (`plan/07` §7, `plan/09` Phase 0 AC 6).** Zero reviews, testimonials, ratings, stars, Trustpilot marks, partner names, partner photos, delivery photos or counts on any page this spec renders, asserted by test over both states in all locales — the real-only ruling of 2026-09-08 applied to the page type `plan/02` §5.2 would most like to fill with them.
- **Geo-blocking (EU 2018/302) and ADR-0006.** Every corridor URL is reachable from anywhere, identical for everyone, never redirected, and never varied by IP. A destination that is not live gets an honest "not yet" — explicitly allowed by the Regulation (`plan/07` §3).
- **Accessibility (EAA / WCAG 2.1 AA).** One `<h1>`, a labelled breadcrumb with `aria-current`, the facts block as a description list, the calendar as a captioned table with header scope, FAQ questions as real headings (no accordion to trap or hide), 200% text reflow, contrast pairs from the manifest, axe zero serious/critical on both states and the hub with no exception list, plus a manual VoiceOver pass on the corridor page recorded in the runbook (the phase-gate item spec 004 established).
- **Logs / PII.** No PII exists to leak: no input, no cookie read, no query parameter consumed, and no per-request log line beyond the existing `request_id`/`locale` fields. The sitemap and robots handlers log nothing. Structured data contains no personal data and no fabricated entity.
- **Security.** No new dependency, no new origin, no inline script — ADR-0016's allowlist policy is unchanged, and `img-src` needs nothing new because the corridor renders no image in Phase 0.

## 9. Acceptance criteria

Content model and the gate
- **AC-1** Every file under `content/corridors/` parses under `CountryLocaleContentSchema` at build time; a malformed or missing required field fails the build naming file and field; `pnpm build` and `pnpm test` succeed with `DATABASE_URL` unset and no network access, and `pnpm check:no-db` covers every file this spec adds.

## 11. Observability

- **CI is the observability surface**, as in specs 004–006, and it gains three blocking signals: the `corridor-check` job (content quality), `seo:validate` running against the **real** built URL set rather than fixtures (hreflang, sitemap, schema), and the extended Lighthouse/axe/visual sets. A failure names the country, the locale and the rule.
- **A published-set summary** is printed to the GitHub step summary by `corridor:check`: per locale, the number of corridor files, how many are `reviewed`, how many pages exist, how many are indexable, and the total indexable URL count. This is the number the `seo-auditor` compares against "countries with `guide_published = true OR status = live`" (`plan/02` §5.1), and the number the founder watches as native reviews land.
- **Logs**: no new request-scoped field; `request_id` and `locale` continue to carry every line; the sitemap and robots handlers log nothing. No PII can enter a log from these routes because they consume no input.
- **Analytics**: the `page_type` dimension value `corridor` and the `select_destination` event's `source: corridor` are declared here and implemented by spec 023 (`plan/04` §14), so the names are not invented twice.
- **After the indexing flip**: Search Console coverage and impressions per folder are the real signal (`plan/02` §16, `plan/09` Phase 0 KPI "indexed guides and impressions"); a `/seo-audit <corridor set>` run is a phase-gate item recorded in the runbook, and the 13–16 Oct hardening window is where it runs.
- **Alerts**: none (Phase 0 has no on-call; spec 025 owns alerting). A broken corridor is a red required check, not an incident.

## 12. Rollout

- **Feature flags** — all data, none behavioural at runtime: `countries.ts` `guidePublished` and `corridorPagePublished` (per destination, read only through their two existing predicates), `site-links.ts` `published` (per link id), the presence of a content file with `reviewed: true` (per locale), and the env-gated `isIndexingEnvironment()`. No new ADR is proposed.

Corrected (an interpretation of a hard requirement, not a relaxation of it):

- **`own-slug-in-body` flags the slug only in URL shape** — adjacent to a `/` or a `-`, matched with

  "Poland-based".
